Add `measurementField()`: a number field storing a canonical value in one storage unit while each admin edits and reads in their own preferred unit. Eight presets ship built in (body weight, person height, distance, mass, length, volume, temperature, speed) as spreadable option bundles, or declare `storageUnit`/`units`/`preferenceKey` directly for anything else; units are constrained only by dimension, and generics narrow those options to the storage unit's dimension when it's a literal. Compound entry (feet and inches, stone and pounds) stays display-only.

- Display unit resolves per viewer: a payload-preferences pick keyed by `preferenceKey` (shipped presets keep their own bucket, free-form fields default to the storage unit's dimension) that follows the viewer across devices and flips every field sharing that key at once, then the field's own `fallbackUnit`, then the plugin's `fields({ measurement: { defaultUnits } })`, then the field's `localeDefaults`, then a per-dimension locale-default table (vendored CLDR data for US/Liberia and UK/Myanmar imperial units, metric everywhere else), then the field's first unit.
- Custom units and dimensions: serializable linear or affine unit definitions (`custom: { units, dimensions }`) travel with the field's client props, so a frontend can rebuild the same engine with `createEngine(custom)`. A unit with no `Intl.NumberFormat` identifier (`intlUnit: null`) formats as a plain decimal plus its short label.
- The editable input's round-trip behavior is controlled by `precision` (see below); readable mode's default draft policy repaints at display digits, exact mode's faithful draft policy shows the shortest string that round-trips to the exact stored value.
- The unit affordance is now the value's adjacent chip, doubling as the popup trigger, rather than a separate far-right badge.
- The stored value is a plain number column: native sort, filter, and group-by, and zero-migration adoption on an existing numeric column by matching `storageUnit` to what's already there.
- `min`/`max` are expressed in the storage unit and enforced by Payload's native number validation; the edit view shows bounds converted to the display unit.
- `@10x-media/fields/measurement/utils` exports the conversion and formatting engine (`convert`, `formatMeasurement`, `decompose`/`compose`, `resolveDisplayUnit`, `systemForLocale`, `createEngine`, `unitLabel`, `unitsOfDimension`, `UNITS`) standalone for frontend use.
- The list view's cell is now a server component too, so `fields({ measurement: { defaultUnits } })` reaches list cells the same way it reaches the edit view; `defaultUnits` also accepts a per-request resolver function for tenant-aware policy, called with `req` undefined from cells since Payload's cell components carry no request.
- `fields({ measurement: { persistPreferences: false } })` makes the unit preference provider session-only, for kiosk or shared-account admins: it skips both the read on mount and every write.

`precision` controls how a value round-trips between storage and the edit view, via two modes and four knobs. Pass a bare `'readable' | 'exact'`, or a `{ mode?, storage?, entry?, draft?, display? }` object to override individual knobs on top of a mode's defaults. `storage` (integer 0-12, default 6) is the fraction digits kept in the storage unit, applied to every write path including the REST and Local API; it is the same universal granularity contract regardless of mode, and can deliberately break entered-unit round-tripping while healing import noise. `entry` (`'quantize'` default in readable mode, `'free'` in exact mode) rounds a typed value at its own display digits, in the unit it was typed in, before converting. `draft` (`'display'` in readable, `'faithful'` in exact) controls whether a saved value repaints straight at display digits or escalates digits until it round-trips exactly. `display` is the per-unit fraction-digit map the field's old top-level `precision` option used to be, now nested here. A field's own `precision` wins over `fields({ measurement: { precision } })`, which wins over the engine default (`readable`, `storage: 6`); merging is per knob, and `display` merges per unit key. A dirty guard backs readable mode's WYSIWYG contract: only an input the viewer actually typed into ever commits its displayed value, so an untouched compound part, or a field re-rendered after a display-unit switch, always commits the exact value already on disk.

Additive: new measurement field family; no changes to existing families or stored data. Precision defaults (`readable`, `storage: 6`) reproduce this changeset's originally shipped behavior for every knob except two: the draft-repaint default, which now truncates to display digits instead of always showing a faithful full-precision draft, and the entry default, which now quantizes a typed value at its own display digits instead of always keeping it free; both are new in this same unreleased change, so nothing published has to migrate.
