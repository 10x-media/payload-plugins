Payload 4 support, on Next.js and TanStack Start. `next` and `@payloadcms/next` are no longer peers. Audit fields move onto Payload 4's own `authorship`: the plugin no longer adds or stamps `createdBy` and `lastModifiedBy`, and `auditFields`, `defaults`, `createdByField` and `lastModifiedByField` are removed. The new `authorshipFields` option (`true`, or `{ collections, globals }`) shows Payload's `createdBy` and `updatedBy` in the admin through the plugin's read-only field; `auditRelationshipField` stays for fields of your own. `posts: true` now means the log only. Stored values need moving across (`lastModifiedBy` becomes `updatedBy`, a plain id becomes `{ relationTo, value }`); the upgrading page has the MongoDB script and the Postgres migration statements. The view is built from Payload 4's list parts: its list header with the debug actions, a list-controls filter band where Event opens a popup of switches and the field filters open a section under the band, and Payload's page controls pinned to the bottom; the `paginationInfo` translation is gone. Badges, rows and the diff use Payload 4's tokens. The view reads repeated query keys on TanStack Start, which hands them over as `key[0]`, `key[1]`. The relationship map that keeps diffs and snapshots to ids is built from the sanitized config on first use, so Payload's own `createdBy` / `updatedBy` (and fields other plugins add later) are stored as references rather than the populated user. Relationship paths resolve blocks named by slug from the config's `blocks`. The debug endpoint queues retention jobs with `overrideAccess: true`, since Payload 4 applies access to `jobs.queue` by default. The log collection opts out of Payload 4's default versions and authorship. Requires Payload `4.0.0-beta.7`. See Upgrading in the docs.
