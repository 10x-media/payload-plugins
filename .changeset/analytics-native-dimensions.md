"@10x-media/analytics": minor
---

**Additive: native dimensions.** The native engine now serves `referrer`, `region`, `city`, `browser`, `os`, `language`, `utmSource`, `utmMedium`, `utmCampaign`, `utmContent` and `utmTerm` as breakdown dimensions, from the rollup and the filtered read paths alike, and all eleven are filterable with `eq` and `contains`. Browser and OS are classified from the user agent at ingest with a small built-in table, language from the request's first accepted language, and the campaign keys (case preserved, capped at 128) from a new `query` field the tracker sends with pageviews. The referrers, browsers, operating systems and campaigns widgets therefore rank rows on a native-only install instead of being skipped for lack of a serving adapter. Native's `filters` set is now every dimension it serves except `goal`, whose completions live in a json column rather than a field a `where` can compare.

**Additive: `capture.autoCapture.query`** (default true). The tracker sends each pageview's query string, without its leading `?` and capped at 512 characters, so ingest can extract the five `utm_*` keys. The raw query is never stored, only those five values; set the option false to stop sending it at all, at the cost of the campaign breakdowns.

**Breaking (native installs):** the events collection gains nine text columns (`browser`, `os`, `language`, the five `utm*`, and `referrerHost`, the bare host the `referrer` dimension groups and filters on). Postgres migrate-mode installs must run the migration in the native docs before upgrading; it is idempotent and deliberately not reversible, since dropping the columns would discard already-attributed events. Mongo needs nothing, and push-mode installs pick the columns up on the next boot. Events ingested before the migration keep their old attribution: nothing is backfilled.

**Additive: a group-by picker per breakdown tab.** Each breakdown tab in the analytics view read one dimension, so the eleven new ones were unreachable in the view, and most had no widget either. A tab that groups by more than one dimension the source serves now carries a **Group by** select beside the row limit: technology switches between devices, browsers and operating systems, geography between countries, regions, cities and languages, sources between the source dimension, the referrer and every campaign key. The pick is URL state (`dim`), omitted when it is the tab's default, and dropped when the selected source cannot serve it. Breakdown widgets pass their own dimension into their view link, so the browsers, operating systems, referrers and campaigns widgets now open the view on the grouping they were showing.

**Behavioral (the Sources tab's default):** the tab now opens on `source` rather than `referrer`. That is no change on native, which did not serve `referrer` before this release, but a provider serving both (Plausible, GA4) opens the Sources tab on the derived source instead of the referring host it used to rank. The referring host is one pick away in the new **Group by** select, and an existing link naming `tab=sources` opens on the new default unless it also carries `dim=referrer`.

**Behavioral (the breakdown panel while it refetches):** a read kept on screen through a refetch answers the grouping asked for when it was issued, so switching tab or dimension used to rank the previous grouping's rows under the new column header with no labels at all. The panel now shows its skeleton until the read for the grouping on screen lands.

**Fixed:** bar-list rows are keyed by rank rather than by label. Two rows sharing a label (a provider answering an unattributed bucket as an empty string) collided, and React stranded the duplicates in the DOM across a rerender, leaving rows on screen that belonged to no read.

**Behavioral:** the `referrer` dimension groups by the referring host (lowercased, `www.` stripped) and excludes same-site referrals, so a site's own domain can never top its own referrers breakdown; the `source` dimension calls those visits `Direct`. `source` now compares the event's own hostname case-insensitively, so a `Referer` differing from the site's host only in case counts as the one self-referral rule rather than as its own bucket. Stored referrers lose their query string and fragment and are capped at 512 characters (a same-origin referrer carries the previous page's whole URL, tokens included). Geo values (`country`, `region`, `city`) are capped at 128 characters. An ingest body whose `referrer` is not a string answers `202` and drops the field instead of failing with a `500`.

**Performance:** rollup and seen-ledger writes are batched per flush, one multi-row statement each, so a fully attributed pageview costs 4 database round trips instead of 161, and a buffered batch pays those writes once for the whole batch rather than once per event. Counting is unchanged.

**Storage:** rollup and seen-ledger rows grow with the cardinality of the new dimensions (referrer host, city, `utmContent`, `utmTerm`), plus one extra bucket set per distinct hostname you ingest from. `retentionDays` prunes events and the seen ledger only, never rollups, so plan storage for that tail.
