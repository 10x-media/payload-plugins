**Additive: a configuration change invalidates that scope's cached reads.** Correcting a provider document, or adding or editing a goal, used to leave every cached read in place until its TTL ran out, up to an hour on most sources, because only the in-process lookup maps were cleared. Every cache key now carries a per-scope cache epoch, an opaque token kept in `payload.kv`. Saving or deleting a provider document or a goal document bumps the epoch of the scope it belongs to, and of the scope it left when a document moves between scopes, so the next read of that scope misses and asks the source again. Old entries are not deleted; they expire by TTL under keys no read asks for. An instance reads a scope's token at most once every ten seconds, so a change made on one instance reaches the others within ten seconds. A token that cannot be read falls back to `0` with a logged warning and never fails an analytics read; for that ten second window the instance may serve entries written before the bump it could not see. A bump that fails, or has not settled after two seconds, is logged and dropped rather than failing the save that triggered it.

**Additive: `POST /api/analytics/refresh` and a Refresh button.** The endpoint bumps one scope's epoch and answers `{ "epoch": "<token>" }`. It takes the same authentication and `access.read` as the read endpoints, and an optional `scope` in its JSON body that only a platform reader may name, answering `400 untrusted_scope` otherwise, as on the query endpoint. `scope: "*"` bumps the install-wide epoch, which is what a cross-scope read's entries key on. The analytics view's toolbar gains a **Refresh** button that calls it and reissues the cards, trend, breakdown and goals sections; the realtime strip and already-rendered dashboard widgets pick the bump up on their own next read. `refreshCache(apiRoute, { scope, signal })` is exported from `@10x-media/analytics/client` beside `fetchQuery`, with `RefreshRequest` and `RefreshResponse` in `@10x-media/analytics/types`.

**Behavioral: the cache key format changed.** Every key now carries the epoch as its second segment, so entries written by the previous release are never read again and every read misses once after the upgrade. Nothing needs to be cleared by hand, and the orphaned entries expire on their own.
