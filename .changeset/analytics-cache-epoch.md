**Additive: a configuration change invalidates that scope's cached reads.** Correcting a provider document, or adding or editing a goal, used to leave every cached read in place until its TTL ran out, up to an hour on most sources, because only the in-process lookup maps were cleared. Every cache key now carries a per-scope cache epoch, an opaque token kept in `payload.kv`. Saving or deleting a provider document or a goal document bumps the epoch of the scope it belongs to, and of the scope it left when a document moves between scopes, so the next read of that scope misses and asks the source again. Old entries are not deleted; they expire by TTL under keys no read asks for. An instance reads a scope's token at most once every ten seconds, so a change made on one instance reaches the others within ten seconds. A token that cannot be read falls back to `0` with a logged warning and never fails an analytics read; for that ten second window the instance may serve entries written before the bump it could not see. A bump that fails, or has not settled after two seconds, is logged and dropped rather than failing the save that triggered it.

**Additive: `POST /api/analytics/refresh` and a Refresh button.** The endpoint bumps one scope's epoch and answers `{ "epoch": "<token>" }`. It takes the same authentication and `access.read` as the read endpoints, and decides scope through the same code the query endpoint reads with, so it refuses every request that endpoint refuses: only a platform reader may name a `scope` in the JSON body, and on a scoped install a request that resolves no scope at all is refused too, both with `400 untrusted_scope`. `scope: "*"` bumps the install-wide epoch, which is what a cross-scope read's entries key on; a tenant's reads key on that tenant's own epoch and are not refreshed by it. A body over 4 KiB answers `413 payload_too_large`. One instance bumps a given scope at most once every five seconds for this endpoint, answering the token already in force inside that window, so a looped call cannot turn a scope's cached reads into provider calls over and over; the document hooks are never debounced. The endpoint is state-changing and cookie-authenticated, so configure Payload's `csrf` allowlist on any install that exposes it. The analytics view's toolbar gains a **Refresh** button that calls it and reissues the cards, trend, breakdown and goals sections; the realtime strip and already-rendered dashboard widgets pick the bump up on their own next read. `refreshCache(apiRoute, { scope, signal })` is exported from `@10x-media/analytics/client` beside `fetchQuery`, with `RefreshRequest` and `RefreshResponse` in `@10x-media/analytics/types`.

**Behavioral: the cache key format changed.** Every key now carries the epoch as its second segment, so entries written by the previous release are never read again and every read misses once after the upgrade. Nothing needs to be cleared by hand, and the orphaned entries expire on their own.
