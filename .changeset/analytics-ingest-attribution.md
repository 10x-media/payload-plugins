"@10x-media/analytics": minor
---

A native event is attributed to the request that carried it, not to the hostname its body claims.

**Breaking:** the hostname a native event is stored under is now the host the request carried (the `x-forwarded-host` entry `n` from the right where `trustedProxyHops` is `n >= 1`, else `Host`), and the body's claim is ignored. The forwarded chain is counted from the trusted end exactly as `x-forwarded-for` is, because a proxy that appends rather than replaces leaves the client's own value at the head of it; a chain shorter than `n`, or an entry that is no hostname, falls back to `Host`, whose peer is the trusted proxy. `Origin` is never read: a scripted client can pair a valid `Host` with any `Origin` and mint unlimited hostname bucket families inside one scope, which is the hole this closes. An install whose beacons already post from the site they are counting sees no change, because the request's host is the page's host; an install whose tracker posts to a different host than the page runs on sees its stored hostname change, and should use the new `hostname` resolver form.

**Breaking:** there is now one definition of a hostname, and config entries, the request host, a resolver's answer and a form goal action's host are all held to it. A value is lowercased and loses its port, its brackets and every trailing root dot, and must then be dot-separated labels of `a-z`, `0-9`, `_` and `-` (every IPv4 literal included) or an IPv6 literal of hex groups and colons, within 253 characters. `example.com.`, `example.com..` and `Example.COM:3000` are therefore one hostname rather than four bucket families, `[::1]:3000` is stored as `::1` rather than `[::1]`, and a name over 253 characters is refused instead of truncated into a name of its own. Anything else (a leading or doubled dot, an unclosed bracket, a percent-encoded or non-ASCII spelling, a non-numeric port, a scheme) drops the event.

**Breaking:** on an install with a `scopeResolver`, an event whose request resolves no scope is dropped instead of being stored install-wide, unless its resolved hostname is listed in the native adapter's `platformHostnames`. A dropped event answers exactly what an accepted one answers, `202` with `{ ok: true }`, and nothing per event is logged, so the endpoint is no oracle for which hosts or tenants exist.

**Behavioral:** the first drop of each reason writes one `warn` line, naming the `scopeResolver` or the `hostname` option to look at, and every later drop of that reason is silent for the life of the process. A public endpoint must not be a log amplifier, since an attacker would otherwise choose how much it writes, but a misconfigured resolver discarding all traffic should not be invisible either.

**Breaking:** the ingest body's `hostname` is optional, and a body carrying one is only type-checked. A missing `hostname` no longer answers `400`; a non-string one still does. `trackServerEvent` is unaffected and still requires its own, since trusted server code has no request to attribute an event to.

**Additive:** `native({ hostname })` takes `'request'` (the default), a list of hostnames (the request host is stored only when the list holds it, and this is the form to use on a single-site install with no `scopeResolver` and no edge validating `Host`), or an `EventHostnameResolver`, `({ claimed, req, scope }) => string | null`, that decides per event, where `null` drops it and a throw drops it too. It is named apart from the binding `HostnameResolver`, which names the hostname a document is read under. A resolver's answer must itself be a hostname: an id, a slug or a label drops the event rather than being stored as free text per event. List entries are validated at boot: a scheme or a port in an entry, or an empty list, fails the boot rather than silently dropping every event.

**Additive:** `native({ platformHostnames })` names the platform's own domains on a scoped install, which ingest under the null scope rather than being dropped. The list is static on purpose: those domains change with a deploy, not with a signup. Tenant domains never belong in it, because a tenant's custom domain is tracked the moment its document is saved, through the install's own `scopeResolver`.

**Additive:** `analytics({ trustedProxyHops })` sets how many proxies in front of the app are trusted, counted from the right of `x-forwarded-for`. It is plugin-level because one helper reads the client address for the native visitor hash, for geo, and for the capture proxy's upstream `X-Forwarded-For`. Unset keeps today's leftmost entry, which is correct for honest traffic and client-writable otherwise. At `n >= 1` the forwarded chain is the only source, and a chain shorter than `n` yields no address rather than falling back to the client-writable `x-real-ip`. There is no default of `1`: an install behind a CDN plus a proxy would then read the CDN's address for every visitor, collapsing geo and the visitor hash onto one value.

**Additive:** `GeoResolver` gained an optional second argument carrying `trustedProxyHops`, so a resolver that does its own IP lookup reads the same address the rest of the pipeline does. `maxmindResolver` honors it. A one-argument resolver still type-checks and still runs. `GeoResolverOptions`, the type of that argument, is exported from `@10x-media/analytics/geo` beside `GeoResolver`.

**Behavioral:** a binding's `hostname` is reduced to the bare lowercased host before it reaches an adapter query, so a tenant domain stored as `https://Example.com/` or with a port still matches the hostnames the native engine writes, which are compared exactly. A value that is no hostname at all reaches the adapter unchanged.

**Breaking:** `trackGoalAction` no longer stores the submitting request's `Host` as given. It resolves the `hostname` option first, then that request under the native adapter's own `hostname` policy (so a forged host the ingest endpoint would refuse is refused here too), then the host of `serverURL`. The scoped-install drop rule does not apply, since a submission's scope comes from the form document. With none of the three (no `serverURL`, and a request with no usable host), the completion is not recorded at all: the action writes one `warn` line for the life of the process and returns, rather than throwing inside a submission it is not essential to. The policy is read off the very adapter the event would be written through, so one adapter cannot judge a hostname another one stores. `trackServerEvent` called directly by server code is unchanged: it is trusted, supplies its own hostname, and still requires one.

**Additive:** an adapter's `ingest` seam may expose `hostname`, which applies that adapter's own hostname policy to a request. The native adapter provides it, and it is how the form goal action attributes exactly as the endpoint does.

**Behavioral:** an existing single-site install sees the same hostname it saw before in the common same-origin case, since the request's host is the page's host there. The visitor hash and the same-site referral check both key off the resolved hostname rather than the claimed one, so a forged body no longer splits one visitor across hostname buckets. The salt, timezone and goal resolvers now run only for an event that will be kept.

Rate limiting is deliberately not part of this. The plugin decides what one accepted request may write; how many requests are accepted belongs to the edge, where a per-IP limit can throttle an abuser instead of the whole install's traffic.
