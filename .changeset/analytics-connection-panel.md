**Additive: a Test connection button on provider documents.** The sidebar of a vendor document shows what its connection last came to (Connected, Not connected, No answer, Not checked), when it last worked and failed, the vendor's own words and until when reads rest, and checks the saved settings with the vendor's cheapest read on a click. Ordinary reads keep the result current. A save that changes how the document connects (a key sent again, another host, ID, provider or scope) clears the result; any other save keeps it. Where the vendor did not word a failure itself (a refused host, a network error), the panel shows translated advice alone, which names what to check for each vendor: the Region for PostHog, the Property ID and the property access for GA4. A reader who may not edit the document sees the button disabled, with the reason. The analytics view shows the vendor's words under a source's setup error, and when the source last worked, to a reader who may read its document. The result is kept in `payload.kv` under `analytics:provider-status:<document ID>`, so no table and no migration are added, and answered by `GET` and `POST /api/_x/provider-status?id=`, which take the caller's own read and update access to the document. When the plugin knows why a check failed, `errorReason` says so and the panel says it in the admin's language: a key or an ID the check needs is empty (`incomplete`), or the vendor does not know the site (`unknownSite`, self-hosted Umami). Adapters may implement `checkConnection(ctx)` (`ConnectionCheckContext`); every built-in vendor adapter does. Upgrade: run `pnpm payload generate:importmap`, so the provider form renders the Connection panel.
