Payload 4 support, on Next.js and TanStack Start. The plugin's own Local API calls (the form read at submit time, published consent versions, queued action and poll-close jobs) pass `overrideAccess: true`, as Payload 4's Local API applies access by default; resolvers you pass the plugin (`consent.sources`, `email.departments`, `email.fromAddresses`, calculation sources, poll option and outcome resolvers) need the same. `forms`, `form-submissions` and the poll votes collection opt out of Payload 4's default versions, and submissions and votes out of its core authorship, so they stay as on Payload 3; `forms` keeps Payload's `createdBy` / `updatedBy`. The poll-close job skips leased jobs through Payload 4's `processingUntil`. The flow and calculation JSON fields describe their generated types through `jsonSchema`. The admin takes the Payload 4 look: add and remove controls are Payload's ghost buttons with its icons, the flow builder moves steps with chevron buttons and uses Payload's blocks header, the calculation builder, condensed arrays, byte-size input and submission answers use Payload 4's tokens and `.form-input`, and the consent retention notice is a default banner. `@payloadcms/*` peers are `^4.0.0-beta.7`. See Upgrading to Payload 4 in the docs.
