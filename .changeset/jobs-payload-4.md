Payload 4 support, on Next.js and TanStack Start. Reliability now builds on Payload 4's processing lease (`processingUntil`, tuned through `jobs.processingLease` in the Payload config) instead of running its own: a job whose worker died becomes claimable again once Payload's lease lapses, and the plugin counts each such run in `recoveryAttempts` and dead-letters the job at `maxRecoveries` instead of running it. The sweeper is gone with it: `reliability.jobLeaseTtlMs`, `heartbeatIntervalMs`, `sweepIntervalMs`, `serverless` and `requireConcurrencyControl`, the `queue-sweep` endpoint, `runSweep`, `createJobLeaseStore`, the `sweeper` leader role, and the `leaseExpiresAt` and `fenceToken` fields are removed; `serverlessPreset()` takes no `maxDurationMs` and `vercelCrons()` returns only the run entry. `releaseClaims(payload, ids)` is new; a worker's drain uses it to hand stragglers back at once. The `payload-jobs` collection, which Payload 4 locks down, is readable by whoever passes `jobs.access.run` and creatable by whoever passes `jobs.access.queue` (a logged-in user by default); update and delete stay denied. The list's Status column loads the fields it derives from even when they are hidden, since Payload 4's list selects only visible columns. The dashboard takes the Payload 4 look: styles use the Payload 4 tokens, the health bar sits in the list gutter, header facts use Payload's tooltip, Succeeded is green and Running takes the blue that was Succeeded's, and a custom input editor is wrapped as a field so it is spaced like one. The health bar's status filters open in Filters, and Cancelled and Failed now filter correctly from a link. "Lease expires" shows Payload's `processingUntil`. See Upgrading to Payload 4 in the docs.
