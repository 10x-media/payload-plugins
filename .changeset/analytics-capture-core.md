---
"@10x-media/analytics": minor
---

**Breaking: first-class event capture.** Capture-capable adapters (native, PostHog, Plausible, Umami) now declare a `capture` descriptor: proxy routes, a snippet, and a public client config. An adapter declares one only when the public config capture needs is present, so a read-only PostHog (no `projectToken`) or a Plausible with neither `domain` nor `scriptId` gets no proxy route, no snippet, and fills no slot; reads are unaffected. The descriptor drives three new surfaces:

- A first-party runtime proxy at `/api/analytics/p/<slot>/*` (public; declared routes only; GET, POST and OPTIONS served, and PUT, PATCH and DELETE answered 405; cookies and authorization never forwarded and `set-cookie` never returned; body cap and timeout via `capture.proxy.{maxBodyBytes,timeoutMs}`; 404 for unknown slots or paths, 413 over the cap, 400 on a body that dies in transit, 502 on upstream failure). No rate limiting yet.
- `captureRewrites([{ path, adapter }])` from `@10x-media/analytics/next` for installs that prefer Next rewrites. `posthogProxyRewrites` now wraps it and is deprecated; its emitted param name changed from `:path*` to `:p*` (equivalent for Next). Root mounts and nested or duplicate mount paths throw.
- A public `GET /api/analytics/tracker` endpoint plus `getTrackerConfig(payload, { headers })` and the `AnalyticsScripts` server component (`@10x-media/analytics/rsc`) that resolve per-request capture config for up to two slots, `global` and `tenant`, one adapter each, deduped when both resolve to the same adapter. Vendor snippets are rendered only for slots that do not require consent; consent-gated vendors load after `consent('granted')`.

**Breaking: native engine.** Ingest accepts `type: 'goal'`, plus `value`, `currency` and `scrollDepth` on any event; a missing or non-string `name` on events and goals answers 400 (a nameless `type: 'event'` previously ingested); `name` is capped at 128 characters and `props`, previously stored verbatim, is sanitized to at most 20 flat scalar keys. Config `goals` (`{ slug, name, match: { kind: 'goal' | 'event' | 'path' }, value?, currency? }`) are matched at ingest into `goal` rollup buckets and stamped onto the stored event. `DimensionKey` gains `goal`, `RollupDelta.inc` widens to the full counter set, and `AdapterRegisterContext` gains a required `resolveGoals(req, scope)` that any code building that context by hand must supply. Existing native installs need a migration adding four numeric rollup counters, the `value`, `currency`, `scrollDepth` and `goals` event fields, and the `goal` event type (snippet in the native docs; on Postgres the enum change is irreversible).

**Behavioral:** native serves `conversions`, `revenue` (summed in the event's currency, no conversion) and `scrollDepth` (average over the pageviews that reported one), and a `goal` dimension that is groupable but not filterable. A `goal` event counts under `events` and never appears in the `event` dimension breakdown. Goal buckets also accrue visitor and session rows. `autoCapture` is on by default except `scrollDepth`. Consent defaults per tracker family: vendors require it, native does not.

**Additive:** new subpaths `@10x-media/analytics/tracker` (dependency-free browser tracker: `page`, `track`, `trackGoal`, a consent gate whose decision persists under the `analytics:consent` storage key and whose pending events wait in a bounded in-memory queue, SPA route tracking, scroll depth, outbound links, file downloads, `data-analytics-goal` on click and submit) and `@10x-media/analytics/react` (`AnalyticsProvider`, `useAnalytics`, `TrackerBoot`). `useAnalytics()` also works without a provider once `TrackerBoot` has booted. Vendor snippets are self-sequencing (PostHog's official queued stub, Plausible's per-site stub) and carry the CSP nonce, which the PostHog stub propagates onto the bundle it injects. New options: `capture.{slots, paths, consent, autoCapture, proxy}` and `goals` (array, or `{ defaults }`); `capture.slots.<slot>: false` disables a slot; `capture.consent` overrides per slot, per adapter id, or through a resolver. `AnalyticsAdapter` gains optional `capture` and `ingest` members; PostHog gains `region` and `projectToken`; Plausible gains `domain` and `scriptId`; Umami's `host` also serves as the app origin for capture. The widget pickers offer `conversions`, `revenue` and `scrollDepth`, and a new `analytics-breakdown-goals` block lists goal completions.
