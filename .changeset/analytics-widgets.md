**Additive: more widgets.** Five new breakdown widgets (referrers, browsers, operating systems, campaigns, events) register from the same table as the existing ones, each gated on its own dimension. A goals widget (`analytics-goals`) lists conversions, revenue and conversion rate per goal for the widget's timeframe, under each goal's own name, with a previous-period delta on conversions when comparison is on; it needs a source that serves both `conversions` and the `goal` dimension, and costs one engine read, plus one for the rate's denominator where the source serves `visitors`, plus one for the deltas with comparison on. Every built-in widget gains an "Open in Analytics" link that opens the analytics view on the widget's source, range, metric or tab; the source is the adapter that actually served the widget, not the id it asked for, and the link serializes against the install's own `view.defaultRange` / `view.defaultMetric`, so anything already on a default is left out. A custom range becomes two day strings in the reporting timezone, clamped to the last 366 days of the window where it is wider than the view can hold; `allTime`, `thisMonth` and `thisYear` are windows the view's range picker does not offer, so those links carry no range and open the view on its default. The link disappears with `view: false`.

`TrendChart` accepts `comparison`, `comparisonLabel`, `comparisonRange` and `label`, drawing the previous period as a muted line on a y-scale covering both series, with a legend that carries the previous window's range and a tooltip row per series. The trend widget gains a "Compare to previous period" checkbox (off by default, absent when `widgets.comparison` is false) that reads the previous window's series through `readForWidgetSeries({ compare: true })`, which now returns `comparisonPoints` aligned to `points` by index. `readForWidget` accepts `comparison: false` for callers that only want totals; `readForWidgetBreakdown` accepts `extraMetrics` and returns per-row `metrics` for them; both surface `stale`.

**Fix:** the view's trend re-dates the comparison series onto the primary axis by index before labelling it. The query endpoint buckets each window on its own week and month boundaries, so at those granularities the comparison could come back a bucket longer or shorter and the chart padded or truncated it silently.

**Behavioral:** the analytics view's trend section draws one chart with the overlay instead of stacking a second chart for the previous period. With the trend widget's comparison ticked, the previous-window read it already made is asked for by day rather than as a total, so an adapter that answers series and totals in separate calls makes one more call for it.

**Fix:** a duplicate row on the native engine's seen ledger is treated as "already seen" rather than thrown. A pageview and a goal event arriving together for the same visitor race on the same ledger key, and the loser's duplicate-key error (Mongo 11000, Postgres 23505) used to escape the ingest handler as a 500.
