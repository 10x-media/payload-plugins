**Breaking (contract): `channel` is a new dimension.** `DIMENSION_KEYS` gains `channel`, right after `source`. Code holding an exhaustive `Record<DimensionKey, …>` needs the new key. `source` and `channel` now mean the same two things on every adapter that serves them: `source` is the visit's named origin (the `utm_source` tag when there is one, otherwise the referrer), and `channel` is the classification of that origin into an acquisition channel, in each source's own vocabulary.

**Breaking (native installs): `source` stores the named origin again, and `channel` stores the classification.** The previous release stored one of six channel tokens in `source`. Native now stores `utm_source`, else the referring host, else the token `direct` in `source`, and one of twelve tokens in the new `channel` column: `direct`, `organic-search`, `paid-search`, `organic-social`, `paid-social`, `organic-video`, `paid-video`, `email`, `affiliate`, `display`, `referral`, `paid-other`. A paid visit is one whose `utm_medium` is `cpc`, `ppc` or starts with `paid`, or whose query carries a Google Ads, Microsoft Ads or TikTok Ads click id (`gclid`, `gbraid`, `wbraid`, `msclkid`, `ttclid`); the platform comes from the referrer host, from `utm_source` by name when there is no referrer host at all, and on the paid path from `utm_source` too when the host names no platform, so an ad click arriving through a network's redirect host keeps its platform. `utm_medium` values `email`, `newsletter`, `affiliate`, `affiliates`, `display`, `banner`, `cpm`, `retargeting`, `remarketing`, `social`, `social-media`, `sm`, `organic` and `search` classify directly. Events also carry `channelVersion`, the version of the rules that classified them, so a later reclassification can find rows written under older rules. The events collection gains the `channel` and `channel_version` columns: Postgres migrate-mode installs add them with the updated snippet in the native docs; Mongo and push-mode installs need nothing. Nothing is backfilled, so rows written by the previous release keep the token they stored in `source`. Because `source` now holds raw `utm_source` values (capped at 128 characters), its rollup rows grow with the number of distinct values an install's traffic carries, one row per value per hostname family, where the old six-token set bounded them.

**Fixed: `fbclid` no longer reads as paid.** Facebook appends `fbclid` to every outbound link, organic posts included, so the previous release overcounted paid traffic. It is now a social signal only: with no referrer host it names the social platform inside whichever of the paid or organic branches the other signals chose, so a visit carrying nothing but `fbclid` is organic social.

**Fixed: a row with no value reads "Not set" and offers no filter.** A source can answer a row with no value for the dimension it was grouped by, PostHog's empty `$channel_type` for a pageview captured outside a session among them. The bar carried no label, and clicking it built an `eq ''` filter the query endpoint rejects, since a filter value is one character at minimum. Such a row now renders the new translated `valueNotSet` key on every dimension and every source, and is inert in the view's breakdowns while the rows beside it keep their click.

**Additive: providers serve `channel` too.** Plausible maps it to `visit:channel`, GA4 to `sessionDefaultChannelGroup`, PostHog to the session's `$channel_type`, and Umami to `/metrics?type=channel`. Each returns its own channel names, rendered as they arrive; native's tokens render through twelve typed `channel*` translations. `channel` is filterable on native, Plausible, GA4 and PostHog, and groupable only on Umami, whose API takes no channel filter.

**Behavioral: the Sources tab opens on channels.** The tab's dimensions now lead with `channel`, then `source`, then `referrer` and the campaign keys, so it opens on the channel overview wherever the source serves one; the named origin and the referring host are one pick away in **Group by**. PostHog gains a Sources tab, which it did not have before. An existing link naming `tab=sources` opens on channels unless it also carries `dim`.

**Additive: a channels widget.** `analytics-breakdown-channels` ranks channels on the dashboard, opening on visitors, and links into the Sources tab; `analyticsDefaultWidgets()` places it after the sources card. The sources widget keeps ranking `source`.
