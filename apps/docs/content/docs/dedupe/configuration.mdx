## Plugin options

| Option | Default | |
| --- | --- | --- |
| `disabled` | `false` | Turns the plugin off. Its collections stay in the schema. |
| `translations` | unset | Overrides for the plugin's strings, per locale. |
| `collections` | `{}` | Per collection: `true` for the merge screen alone, the object below, or `false`. |
| `access.review` | logged in | Who opens the queue, the merge screen and the history. The collection's `read` access on the documents applies too: the queue lists no group with a document the reader may not read. |
| `access.merge` | logged in | Who applies a merge. The collection's `read`, `update` and `delete` access apply too. |
| `requireTransactions` | `false` | Refuse to merge without a database transaction. |
| `maxGroupSize` | `5` | Most documents in one merge, 2 or more. |
| `adapter` | keys | Where candidates come from, see [Adapters](./searching#adapters). |
| `disableJobsQueue` | `false` | Run the save check and the scan inside the request, for a deployment without a job worker. |
| `queue` | `dedupe` | Jobs queue of the `dedupe-check` and `dedupe-scan` tasks. |
| `scan.cron` | unset | Scan every matched collection on a schedule. Needs a job runner. |
| `view` | `{ path: '/dedupe' }` | Admin path; `false` removes the views. `navLabel` renames the sidebar entry, `history: true` (or `{ navLabel }`) adds one for the merge history. |
| `overrides` | `{}` | `keys`, `pairs`, `merges`: a function over the plugin's collection. Hooks are refused. |
| `collectionAccess.read` | nobody | REST and GraphQL read access on the plugin's collections. A merge record holds whole copies of the merged-in documents, of every tenant, hidden fields included. |
| `multiTenancy` | off | `true` or `{ tenantFieldName }`, see below. |
| `events` | unset | `{ emit(event, req) }`, see below. |

## Per collection

| Option | Default | |
| --- | --- | --- |
| `match.fields` | required for search | `{ path, weight, compare?, onDiffer?, key?, tolerance?, toleranceType? }` per field, see [Searching](./searching). |
| `match.minScore` | `0.35` | Lowest score kept as a pair. |
| `match.maxBucket` | `2000` | Larger key buckets are skipped by the scan. |
| `match.candidateLimit` | `200` | Most documents the save check compares. |
| `fields` | derived | `(derived) => spec`, see [Merging](./merging). |
| `absorbed` | `trash`, or `delete` without a trash | What happens to the merged-in documents: `trash` or `delete`. `trash` needs `trash: true` on the collection. |
| `draft` | `false` | On a collection with drafts, merge the latest drafts and save the result as a draft. By default the published documents are merged and the result is published. |
| `checkOnSave` | `true` with a match | Index and check the document on every save. |
| `form.sidebar` | `false` | Saved look-alikes of the typed values in the document sidebar. Needs `match`. |
| `form.confirmCreate` | `false` | Ask before creating a document that resembles a saved one. Needs `match`. |
| `references` | every field pointing here | `(derived) => references`, see [Merging](./merging#references). |

An invalid match config stops the app at startup with an error naming the field.

## Duplicate warnings on the form

```ts
dedupe({
  collections: {
    customers: {
      match: { fields: [/* ... */] },
      form: { sidebar: true, confirmCreate: true },
    },
  },
})
```

The sidebar lists saved look-alikes as the user types; `confirmCreate` asks before a new document that resembles one is saved. Both search as the current user and never block a save when the search fails. `confirmCreate` is skipped on collections with draft autosave.

To place them yourself, import `DuplicatesField`, `ConfirmSaveButton` or `ConfirmCreate` from `@10x-media/dedupe/client` with `collection` and `paths` (the match field paths), or call `useDuplicateCheck({ collection, paths })`.

## Multi-tenancy

```ts title="payload.config.ts"
dedupe({
  multiTenancy: true,
  collections: { customers: { match } },
})
```

Documents of different tenants are never compared or merged together, and the queue and the history show the selected tenant only. A collection without the tenant field shows under every tenant. Set `tenantFieldName` when yours differs from `@payloadcms/plugin-multi-tenant`'s.

## Events

```ts title="payload.config.ts"
dedupe({
  events: {
    emit: async (event, req) => {
      if (event.type === 'merge.applied') {
        await notify(req, `${event.absorbedIds.join(', ')} merged into ${event.survivorId}`)
      }
    },
  },
})
```

Event types: `pair.found` (also when a pair opens again), `pair.dismissed`, `pair.reopened`, `merge.applied`, `merge.failed`, `scan.finished`. A sink that throws is logged and changes nothing. `pair.found` is sent inside the transaction of the save (with `disableJobsQueue`) or of the merge, so one that fails afterwards may have announced a pair it never stored.
