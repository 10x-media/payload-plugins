title: Quick start
description: Install the plugin, track pageviews with the native engine, and see numbers in the admin.
---

This walkthrough uses the [native engine](/analytics/native) so nothing external is required. Swap in a [provider adapter](/analytics/adapters) at any point; everything else stays the same.

## Install

```bash
pnpm add @10x-media/analytics
```

## Configure

```ts title="payload.config.ts"
import { buildConfig } from 'payload'
import { analytics, analyticsDefaultWidgets, analyticsStatRow } from '@10x-media/analytics'
import { native } from '@10x-media/analytics/adapters/native'

export default buildConfig({
  admin: {
    // Widgets render on Payload's Modular Dashboard. The app owns the layout;
    // spread the plugin's defaults into it (or compose your own).
    dashboard: { defaultLayout: [...analyticsDefaultWidgets()] },
  },
  collections: [
    {
      slug: 'pages',
      fields: [
        { name: 'slug', type: 'text' },
        analyticsStatRow(), // pageviews, visitors, sessions, avg duration
      ],
    },
  ],
  plugins: [
    analytics({
      adapters: [native()],
      collections: {
        // Bind documents to the URL path their analytics were recorded under.
        pages: { path: (doc) => (doc.slug ? `/${doc.slug}` : null) },
      },
    }),
  ],
})
```

Then regenerate the import map so the admin resolves the plugin's server components:

```bash
payload generate:importmap
```

## Capture events

Boot the browser tracker from your root layout. It sends pageviews (including SPA route changes), outbound-link and file-download events, and any goal you tag:

```tsx title="app/layout.tsx"
import { AnalyticsScripts, getTrackerConfig } from '@10x-media/analytics/rsc'
import config from '@payload-config'
import { headers } from 'next/headers'
import { getPayload } from 'payload'

export default async function RootLayout({ children }: { children: React.ReactNode }) {
  const payload = await getPayload({ config })
  const tracker = await getTrackerConfig(payload, { headers: await headers() })
  return (
    <html lang="en">
      <body>
        {children}
        <AnalyticsScripts config={tracker} />
      </body>
    </html>
  )
}
```

Outside Next, `initTracker()` from `@10x-media/analytics/tracker` does the same from the browser. Full setup, including consent and the vendor slots, is on [Capture](/analytics/capture).

The native engine's beacon endpoint (`POST /api/analytics/ingest`) stays public, so a host that would rather post events itself still can; see [Native engine](/analytics/native#the-ingest-endpoint) for the event shape.

## Verify

1. Hit a few frontend pages.
2. Open the admin dashboard: the trend, metric, and breakdown widgets show the traffic.
3. Open a `pages` document whose slug matches a tracked path: the stat row shows that document's numbers.
