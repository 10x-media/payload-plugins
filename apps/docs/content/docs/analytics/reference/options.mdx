---
title: Options
description: Every option of analytics(), with its type, its default and what it does.
---

`analytics()` takes one object, `AnalyticsPluginOptions` (also exported as `PluginOptions`). Every path below is checked when the plugin builds the Payload config: a value of the wrong shape, a key no table lists at any level, an id that names no adapter, or a combination the plugin cannot honor fails the boot with a message naming the path. An option an earlier release took and this one no longer does fails the boot too, naming its replacement ([Removed options](/analytics/upgrading#removed-options)).

The [native engine](/analytics/native#options) and each [provider](/analytics/providers) take options of their own, as arguments of `native()`, `plausible()` and the rest. Each of them takes `label`, the source's name in the admin: a string, a map by admin language, or a function per reader ([A source's name](/analytics/providers#a-sources-name)).

```ts title="payload.config.ts"
import { analytics } from '@10x-media/analytics'
import { native } from '@10x-media/analytics/adapters/native'

export const plugin = analytics({
  adapters: [native()],
  capture: { gate: 'all' },
  collections: { pages: { path: (doc) => (typeof doc.slug === 'string' ? `/${doc.slug}` : null) } },
  revenue: { currency: 'EUR' },
  trustedPlatform: 'vercel',
})
```

## Top level

| Option | Type | Default | What it does |
|---|---|---|---|
| `adapters` | `AnalyticsAdapter[]` | required | The [config adapters](/analytics/concepts#sources-and-adapters). At least one, unless `disabled` is set, and no two with the same `id`. |
| `defaultAdapter` | `string` | the first adapter | The source a read uses when it names none. Must be an id in `adapters`. On a scoped install a tenant's default can differ: a provider document flagged **Default for this site**, then `defaultSource`, come first ([A tenant's default source](/analytics/multi-tenancy#a-tenants-default-source)). |
| `platformAdapter` | `string` | none | The id of one config adapter shared by every scope: the platform's own analytics. It fills the [global capture slot](/analytics/capture#capture-slots) unless `capture.slots.global` says otherwise. Must be an id in `adapters`. |
| `disabled` | `boolean` | `false` | Switches the plugin off and keeps its database schema: [below](#switching-it-off). |
| `translations` | `TranslationsOption` | none | Per-language overrides of the admin strings, keyed by the typed keys of `@10x-media/analytics/i18n` ([Translations](/analytics/reference/translations)). A key that is not one of the plugin's own fails the boot. |
| `reportingTimezone` | `string \| TimezoneResolver` | `'UTC'` | The zone days are cut in ([Reporting timezone](/analytics/timezone)). A string `Intl.DateTimeFormat` does not accept as a time zone fails the boot. A resolver answers per scope, also at ingest, and `null` means UTC. |
| `trustedProxyHops` | `number` | none: the leftmost `x-forwarded-for` entry | How many proxies in front of the app to trust, counted from the right of `x-forwarded-for`, when reading a visitor's address; also lets native ingest read `x-forwarded-host` ([Trusted proxies](/analytics/proxy#trusted-proxies)). A non-negative whole number. Cannot be set with `trustedPlatform`. |
| `trustedPlatform` | `'vercel' \| 'cloudflare'` | none: no platform header is read | The platform whose edge headers carry the visitor's address and location ([Geo](/analytics/geo#which-headers-to-trust)). Cannot be set with `trustedProxyHops`. |
| `sdks` | `AnalyticsSdks` | `{}` | Optional packages handed in, so a standalone or serverless build ships them. A production boot warns about one it would load by name. |
| `sdks.ga4` | `{ BetaAnalyticsDataClient }` from `@google-analytics/data` | none | The GA4 Data API client for every GA4 source ([GA4](/analytics/providers#ga4)). |
| `sdks.maxmind` | `{ open }` from `maxmind` | none | The MaxMind reader for `native({ geoDbPath })` and `maxmindResolver` ([Geo](/analytics/geo#maxmind-optional)). |
| `routes` | `{ base? }` | | Where the endpoints answer. |
| `routes.base` | `` `/${string}` `` | `'/_x'` | The path every endpoint the plugin registers hangs off, under Payload's `routes.api` ([Where the endpoints answer](/analytics/reference/endpoints#where-the-endpoints-answer)). |
| `hooks` | `{ afterRead? }` | | Hooks into what the plugin does. |
| `hooks.afterRead` | `AfterReadHook` | none | Runs once for every read answered to a reader, after it is cached, with `{ adapterId, query, result, from, durationMs, payload }`; return a result to answer that one read differently ([Observing reads](/analytics/cache#observing-reads)). |

## `scope`

Tenancy: how a request maps to its [scope](/analytics/concepts#scope). Unset, the install is one scope. [Multi-tenancy](/analytics/multi-tenancy) has the recipe.

| Option | Type | Default | What it does |
|---|---|---|---|
| `scope.resolve` | `({ req, callSite }) => string \| null` | required in `scope` | Which scope a request is for. `callSite` is `'capture'` (a visitor's hit, asked without the user, cookies or authorization header) or `'admin'`. `null` is the whole install; answering `'*'` is refused. |
| `scope.member` | `({ req, scope }) => boolean` | required with `resolve` | Whether the request's user belongs to the scope it selected. `tenantMembership()` reads `@payloadcms/plugin-multi-tenant`'s tenants array; `() => true` opts out. |
| `scope.list` | `({ payload }) => string[]` | none | The tenant scopes the sync task runs over, besides the install-wide pass. |
| `scope.label` | `({ req, scope }) => string \| undefined` | the scope id | What the view's caption and Site select call a scope. |
| `sources` | `{ [adapterId]: { tenants? } }` | `{}`: every config adapter is `'staff'` | Per shared config adapter, which of a tenant's own users read that tenant through it ([Letting tenants read a shared source](/analytics/multi-tenancy#letting-tenants-read-a-shared-source)). Each key must be an id in `adapters`. |
| `sources.<id>.tenants` | `'staff' \| 'tenant' \| 'fallback' \| ({ req, scope, adapterId, ownSources }) => boolean` | `'staff'` | `'staff'`: only readers `access.crossScope.unscopedSource` admits. `'tenant'`: the scope's members too, narrowed to their tenant. `'fallback'`: its members until they read a source of their own. A function: its members when it answers `true`; a throw denies. Anything but `'staff'` needs an adapter with `capabilities.scopedQueries`, or the boot fails. |
| `defaultSource` | `'tenantFirst' \| 'platformFirst' \| ({ req, scope, sources }) => string \| undefined` | none: `defaultAdapter`, else the first config adapter, else the first source the reader may read | A tenant scope's default source when none of its provider documents is flagged the default. `'tenantFirst'` picks the reader's first source from the tenant's own documents, `'platformFirst'` the `platformAdapter`, a function an id from `sources`; one the reader cannot read, or a throw, keeps the default. |

Each may also return a promise. These options only mean something on a scoped install, so each fails the boot without `scope.resolve`: `scope.list`, `scope.label`, `scope.member`, `sources`, `defaultSource`, `access.crossScope`, an adapter id in `capture.slots.tenant`, `capture.paths.tenant`, a `collections.<slug>.scopeField` other than `false`, and `goals.collection.scopeField` or `providers.collection.scopeField` when set at all.

## `access`

| Option | Type | Default | What it does |
|---|---|---|---|
| `access.read` | `({ req }) => boolean` | `isAdminUser`: users of the admin collection (`admin.user`) | Gates every read: the read endpoints, the widgets, the display fields and the read helpers. It never widens which scope a user reads. |
| `access.view` | `({ req }) => boolean` | `access.read` | Gates the [analytics view](/analytics/analytics-view) and the exclusion endpoint. The view shows goal and site names only to a reader `access.read` admits as well. |
| `access.crossScope` | `CrossScopeAccess \| { named?, aggregate?, unscopedSource? }` | scoped: every gate denies; unscoped: every gate is `isAdminUser` and the option cannot be set | Reads past the request's own scope. A function grants all three gates; the object form decides each one, and a gate it leaves out denies. |
| `access.crossScope.named` | `CrossScopeAccess` | as above | Reading a scope the request does not resolve to, by naming it; also who manages another tenant's provider, goal and sync documents. |
| `access.crossScope.aggregate` | `CrossScopeAccess` | as above | Reading every scope at once: `scope=*`, the view's **All sites**, and a scoped request that resolves no tenant. |
| `access.crossScope.unscopedSource` | `CrossScopeAccess` | as above | Reading a tenant through a config adapter rather than its own provider documents ([Who sees what](/analytics/multi-tenancy#4-who-sees-what)). `sources` can let a tenant's own members in as well. |

`CrossScopeAccess` is `({ req, scope?, adapterId? }) => boolean`, told what is asked where the read knows it: `named` the scope it names, `aggregate` `'*'` (or `null` for a scoped request that resolves no tenant), `unscopedSource` the tenant and the adapter. A gate may run once per scope and adapter in a request ([What a gate is told](/analytics/multi-tenancy#what-a-gate-is-told)). Each function may also return a promise.

| `capture.allowedOrigins` | `string[]` | `[]` | Other sites whose pages may send to the ingest endpoint and the capture proxy, each one exact `http(s)` origin ([Beacons from other sites](/analytics/capture#beacons-from-other-sites)). |
| `capture.proxy` | `{ timeoutMs?, maxBodyBytes? }` | | Limits of the [runtime capture proxy](/analytics/proxy#runtime-endpoint). |
| `capture.proxy.timeoutMs` | `number` | `10000` | Milliseconds to wait for the vendor's response headers. A whole number of at least 1. |

| `collections.<slug>.pathField` | `string` | none | A field holding the path, read when `path` is unset or answers nothing. Its value is used as written, so it has to start with `/`; a dotted name reads a nested field. |
| `collections.<slug>.hostname` | `string \| (doc, context) => string \| null` | none: every hostname | Narrows a document's reads to one hostname. |

## `cache`

How reads are cached and how much they ask of their sources ([Caching](/analytics/cache)).

| Option | Type | Default | What it does |
|---|---|---|---|
| `cache.ttl` | `{ aggregate?, realtime? }` | | Seconds an answer stays fresh, each a whole number of 0 or more. A native read reaching into today stays fresh 10 seconds at most whatever they say ([TTLs](/analytics/cache#ttls)). |
| `cache.ttl.aggregate` | `number` | each adapter's `recommendedTtl.aggregate` | For historical reads. |
| `cache.ttl.realtime` | `number` | each adapter's `recommendedTtl.realtime` | For live counts and reads of days still counting. |
| `cache.timeoutMs` | `number` | `15000` | How long a read with nothing cached waits for its source, every retry included. A whole number of at least 1. |
| `cache.concurrency` | `{ global?, perSource?, perScope? }` | | How much reads ask of their sources at once ([Reaching the sources](/analytics/cache#reaching-the-sources)). |
| `cache.concurrency.global` | `number` | `16` | Requests in flight across every vendor source of one instance. |
| `cache.concurrency.perSource` | `number` | `4` | Requests in flight per vendor source that declares no `rateLimit.maxConcurrent`. |
| `cache.concurrency.perScope` | `number` | `8` | Reads with nothing cached one scope may have waiting; past it the query endpoint answers `429`. |
| `cache.warm` | `boolean \| { windowHours?, maxReads? }` | `false` | Turns on the `analytics-warm` task, which reads recent reads again before they expire ([Warming](/analytics/cache#warming)). |
| `cache.warm.windowHours` | `number` | `24` | A read asked for this recently counts as recent. |
| `cache.warm.maxReads` | `number` | `200` | The most reads one run refreshes. |

## `jobs`

|---|---|---|---|

## Switching it off

`disabled: true` switches the plugin off and keeps its database schema:

```ts
analytics({
  disabled: process.env.ANALYTICS_OFF === '1',
  adapters: [native()],
  capture: { gate: 'off' },
})
```

A switched-off install registers the same collections with the same fields and indexes (providers, goals, sync, cache, the native engine's three when `native()` is listed, and `analytics-state` for sync or warming) and the same task names in Payload's jobs, so a development push or a generated migration drops nothing, and every row is still there when the plugin comes back. An adapter's own collections are kept by its `registerSchema`, which every built-in adapter has; a [custom adapter](/analytics/reference/adapter-contract#writing-your-own-adapter) that adds collections in `register` without one loses them while the plugin is off, and a push or a migration then drops them.

Nothing that runs is registered: no endpoint, view or widget. Each task does nothing, and its schedule, kept so Payload keeps the `payload-jobs-stats` global it adds for scheduled tasks, has a hook that never queues a run. What belongs to the collections stays as it is: the providers and goals collections keep their access and their hooks, so editors still manage them in the admin. Payload's job controls stay [restricted to the admin collection](/analytics/native#who-may-run-jobs) as when the plugin runs, which is the one `onInit` a switched-off install adds, and only when it keeps a task. Translations are registered only for the labels of the collections the admin lists. The options are checked as when the plugin runs, except that `adapters` may be empty, which keeps no adapter's collections. The [collection checks](#renaming-the-plugins-collections) run too, and only their warnings go unsaid; their second pass over the assembled config runs only while the plugin is on.

## Renaming the plugin's collections

Every collection the plugin registers takes a `slug` and an `overrides` function, under the option of the feature it belongs to:

| Collection | Default slug | Registered with | Option |
|---|---|---|---|
| Raw [hits](/analytics/native#storage) | `analytics-hits` | `native()` | `native({ collections: { hits } })` |
| [Daily totals](/analytics/native#storage) | `analytics-aggregates` | `native()` | `native({ collections: { aggregates } })` |
| Salts, day markers, leases and heartbeats | `analytics-state` | `native()`, else [sync](/analytics/sync) or [warming](/analytics/cache#warming) | `native({ collections: { state } })`; without `native()`, `jobs.state` |
| [Read cache](/analytics/cache#the-analytics-cache-collection) | `analytics-cache` | every install without `cache.store` | `cache.collection` |
| [Synced daily metrics](/analytics/sync) | `analytics-daily` | `sync` | `sync.collection`, which also takes `hidden` |
| [Provider settings](/analytics/providers#provider-documents) | `analytics-providers` | `providers.collection` | `providers.collection`, which also takes `fields`, `access` and more |
| [Goals](/analytics/goals#5-let-editors-manage-goals) | `analytics-goals` | `goals.collection` | `goals.collection`, which also takes `fields`, `access` and more |

The default slugs are exported for code that queries these collections: `CACHE_SLUG`, `GOALS_SLUG`, `PROVIDERS_SLUG`, `STATE_SLUG` and `SYNC_SLUG` from `@10x-media/analytics`, and `HITS_SLUG` and `AGGREGATES_SLUG` from `@10x-media/analytics/adapters/native`. On an install that renames a collection, use the slug it set.

```ts
analytics({
  adapters: [
    native({
      collections: {
        hits: { slug: 'site-hits', overrides: (collection) => ({ ...collection, dbName: 'raw_hits' }) },
        aggregates: { slug: 'site-totals' },
        state: { slug: 'site-state' },
      },
    }),
  ],
  capture: { gate: 'all' },
  cache: { collection: { slug: 'site-cache' } },
  sync: { collection: { slug: 'site-daily' } },
})
```

`analytics-state` belongs to the native engine wherever `native()` is listed; `jobs.state` names it only on an install without it, where sync or warming registers it for their leases, and the boot refuses `jobs.state` anywhere else. It takes the key `native()` gives the same collection rather than `collection`, which under `jobs` would read as Payload's own `payload-jobs`.

`slug` is the only way to rename a collection, since every part of the plugin reads it under that slug: an `overrides` that returns another slug fails the boot, naming the option to set instead. `overrides` must be a function. It receives the collection as the plugin built it and returns the one to register, so spread what it keeps.

What an override may change: labels and admin settings, a `dbName` for the collection (its table on Postgres and SQLite, its collection on MongoDB), fields and indexes of your own, hooks, and access. Hooks never run on the rows the plugin writes, which go through `payload.db` or the engine's own SQL rather than the Local API.

What fails the boot, with a message naming the collection and the field:

- on the hits, daily totals, state, cache and sync collections, which the plugin writes itself: removing a field the plugin defines, renaming it, changing its type, or moving it into a named `group` or a named tab (a `row` or `collapsible` around it is fine), and making one `localized` or `hasMany`;
- on the same collections, dropping an index or a unique constraint the plugin declares;
- on the same collections, making one of the plugin's optional fields required, or adding a required field without a fixed `defaultValue`: the plugin writes rows without it, and only a value becomes the column's default, while a function runs in Payload's hooks, which the plugin's writes skip;
- on the hits, daily totals and state collections, a `dbName` on any of the plugin's fields: the engine's SQL names each column after its field;
- on the providers and goals collections, `timestamps: false`: every instance notices a saved document by its `updatedAt`, so an edit on one server would never reach the others. Their fields are the editors' to shape, so the boot holds these two to their slug, their timestamps and the name limit below, and nothing else;
- on Postgres, a table name, or an index name Payload builds from it (`<table>_<column>_idx`), over 63 characters, Postgres' limit. Choose a shorter slug, or a shorter `dbName`.

The same checks run again at init, and when a worker booted without `onInit` builds what it needs, against the config every plugin has assembled. A plugin that runs after analytics and changes one of these collections the way an override may not fails there, naming the collection; so does one that removes or renames one, or that replaces the `custom` the plugin marks its collections in (`custom['@10x-media/analytics']`) rather than spreading it, since the plugin finds its collections by that mark.

What the boot warns about, once at init: on the hits, daily totals, state, cache and sync collections, an override that replaces one of the plugin's access functions, or that turns on REST endpoints or GraphQL where the plugin keeps them off. The plugin reads and writes these rows below access control, so the warning is about who else can now reach them.

A new slug or `dbName` names a new table (on MongoDB, a new collection) and moves no rows: on an install that already has data, write a migration that moves them, or keep the names it has.
