The package splits its exports by where they run, so a page loads only what it needs and a server module never pulls the admin UI in. Import from the entry that matches where your code runs:

| Entry | Import it from |
|---|---|
| [`@10x-media/analytics`](#10x-mediaanalytics) | Your Payload config and server code: route handlers, jobs, scripts, Payload's CLI. It loads Payload and no React, admin UI or stylesheet. |
| [`@10x-media/analytics/types`](#10x-mediaanalyticstypes) | Anywhere. Its few runtime values (constants and `readErrorCode`) load no package, and its types erase. |
| [`@10x-media/analytics/attributes`](#10x-mediaanalyticsattributes) | Anywhere, the browser and server components included. It loads no package and no stylesheet. |
| [`@10x-media/analytics/tracker`](#10x-mediaanalyticstracker) | The browser. It loads no package and no stylesheet: no React, no Payload, no Node built-ins. |
| [`@10x-media/analytics/react`](#10x-mediaanalyticsreact) | Client components of your site (`'use client'`). It loads React alone. |
| [`@10x-media/analytics/site`](#10x-mediaanalyticssite) | Server components of your site, such as its root layout. It loads React and Payload, and no admin module. |
| [`@10x-media/analytics/rsc`](#10x-mediaanalyticsrsc) | Server components of the admin. It loads Payload's admin UI and the stylesheet. |
| [`@10x-media/analytics/client`](#10x-mediaanalyticsclient) | Client components of the admin (`'use client'`). It loads Payload's admin UI, Next's navigation and the stylesheet. |
| [`@10x-media/analytics/i18n`](#10x-mediaanalyticsi18n) | Anywhere. It loads no package. |
| [`@10x-media/analytics/geo`](#10x-mediaanalyticsgeo) | Server code, in your Payload config. It loads no package until a MaxMind lookup needs one. |
| [`@10x-media/analytics/next`](#10x-mediaanalyticsnext) | Your Next.js route handlers. It loads Payload only when a route handler first runs. |
| [`@10x-media/analytics/migrations`](#10x-mediaanalyticsmigrations) | Migration files, which Payload's CLI runs. It loads no package. |
| [`@10x-media/analytics/migrations/drop-legacy-mongo`](#10x-mediaanalyticsmigrationsdrop-legacy-mongo) | Payload's CLI, as `payload migrate:create --file`. |
| [`@10x-media/analytics/testing`](#10x-mediaanalyticstesting) | Tests. |
| [`@10x-media/analytics/adapters/native`](#10x-mediaanalyticsadaptersnative) | Your Payload config and server code. It loads Payload and Node built-ins. |
| [`@10x-media/analytics/adapters/plausible`](#10x-mediaanalyticsadaptersplausible) | Your Payload config. It loads no package. |
| [`@10x-media/analytics/adapters/umami`](#10x-mediaanalyticsadaptersumami) | Your Payload config. It loads no package. |
| [`@10x-media/analytics/adapters/ga4`](#10x-mediaanalyticsadaptersga4) | Your Payload config. It loads `@google-analytics/data` only when a read needs it and `sdks.ga4` does not hand it over. |
| [`@10x-media/analytics/adapters/posthog`](#10x-mediaanalyticsadaptersposthog) | Your Payload config. It loads no package. |
| `@10x-media/analytics/styles.css` | Anywhere that draws `BarList` or `TrendChart` outside the admin, where your bundler does not follow the package's own stylesheet imports ([Customizing](/analytics/customizing#outside-the-admin)). |

Each list below is the entry's whole public surface, as the API reports in the package's repository record it. **Stable** exports keep their names within a major release; **beta** ones may change in a minor; **internal** ones are exported only because Payload's import map names them, so do not import them ([Stability](/analytics/reference/stability#release-tags)).
