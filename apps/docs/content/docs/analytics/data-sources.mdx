A **source** is one readable analytics backend for one request: a config adapter, or a provider a tenant configured at runtime. Every widget, display field and dashboard reads through one, and three authenticated endpoints expose the same resolution to your own code: `GET /api/analytics/sources` lists what the request may read, `GET /api/analytics/query` reads it, and `POST /api/analytics/refresh` retires what that reading cached.

## What a source is

Sources come from two places, and they behave identically once resolved:

- **Config adapters.** Whatever `analytics({ adapters: [...] })` declares. Their ids are the adapter ids: `native`, `plausible`, `umami`, `ga4`, `posthog`. Every scope sees them; `kind` is `config`.
- **Runtime providers.** Documents in the [providers collection](/analytics/multi-tenancy#2-register-the-provider-collection-per-tenant), or whatever `providers.resolve` returns, resolved per scope. `kind` is `runtime`.

A runtime provider carries a per-document **instance id**, `<provider>:<docId>` (`posthog:68f3a1...`), so one scope can run two projects of the same provider type without their ids colliding. Its label is the document's `name`, falling back to the adapter label plus a short id. Config adapters keep their plain ids.

Both layers are merged into one registry per scope: the config adapters in config order, then that scope's runtime providers. The registry names a **default source**, which a read that omits `source` uses, and it is always a config adapter: `defaultAdapter` when set, otherwise the first one configured.

## Sources endpoint

`GET /api/analytics/sources` answers the sources the request itself resolves, which is what the widget data-source and metric pickers are built from:

```jsonc
{
  "defaultId": "native",
  "sources": [
    {
      "id": "native",
      "label": "Native",
      "kind": "config",
      "capabilities": { "metrics": ["pageviews", "visitors"], "...": "..." }
    },
    { "id": "plausible:68f3a1", "label": "Alpha Plausible", "kind": "runtime", "capabilities": { "...": "..." } }
  ]
}
```

It requires a signed-in user (`401 unauthorized` otherwise) and passes `access.read` (`403 forbidden` otherwise), both in the plugin-wide [error envelope](#errors), and every answer carries `Cache-Control: private, no-store`. It takes **no scope parameter**, deliberately, so a tenant can never enumerate another tenant's sources. On a scoped install, a request whose scope cannot be resolved, or whose resolution throws, gets `{ "defaultId": null, "sources": [] }` rather than a fallback list: a failed resolution is indistinguishable from a forged one, so it fails closed. An unscoped install has no scope to get wrong and falls back to the config registry.

## Capability gating

Each row carries the adapter's `SerializedCapabilities`, a deliberate allowlist so adapter internals (credentials, rate limits, TTLs) never become client contract:

| Field | Shape | What gates on it |
|---|---|---|
| `metrics` | metric keys the source serves | the `metrics` parameter, and which metric a picker offers |
| `dimensions` | dimension keys it can break down by | the `dimensions` parameter, and which breakdown tabs exist |
| `filters` | dimensions it can filter on | the `dimension` of each `filters` entry |
| `filterOperators` | `eq` / `contains` / `matches` | the `operator` of each `filters` entry |
| `realtime`, `realtimeWindowMinutes` | boolean, plus the window it reports over | whether a realtime surface renders at all |
| `perPageQuery` | boolean | whether per-document [display fields](/analytics/display-fields) can read it |
| `comparison` | boolean, `true` unless the adapter opted out | the `compare` parameter |
| `minGranularity` | the finest bucket it can return | the `granularity` parameter |
| `maxLookbackDays` | days, or `null` for unbounded | how far back a read is narrowed, visibly |

The pickers use it to hide what a source cannot answer; the query endpoint uses the **selected** source's own copy to reject what it was asked for anyway. That is one gate, applied twice, so a request built by hand is validated exactly like one a picker produced.

The [native engine](/analytics/native#dimensions) declares the widest set here: every dimension it classifies at ingest is groupable, and all of them are filterable with `eq` and `contains` except `goal`, whose completions live in a json column rather than a field a `where` can compare. A vendor adapter declares whatever its own API serves, which is usually less.

The contract's dimension keys are `page`, `referrer`, `source`, `channel`, `medium`, `campaign`, `utmSource`, `utmMedium`, `utmCampaign`, `utmContent`, `utmTerm`, `device`, `browser`, `os`, `country`, `region`, `city`, `language`, `event` and `goal`. `source` is the visit's named origin and `channel` its acquisition channel on every adapter that serves them; see [`source` and `channel`](/analytics/adapters#source-and-channel).

<Callout type="info">
Validation is always against the selected source, never against the union of the configured adapters. An install with [runtime providers](/analytics/multi-tenancy) enabled is open-world: a tenant's own adapter serving `revenue` reads it through this endpoint even when no config adapter declares that metric.
</Callout>

## Query endpoint

`GET /api/analytics/query` is the authenticated read primitive: one audited path through access control, scope gating, capability validation and the [cached surfacing engine](/analytics/cache). Build your own dashboard on it, script a report against it, or read it from an admin component. Every section of the [analytics view](/analytics/analytics-view) but its realtime strip reads through it, so whatever those sections show, your own code can read the same way; the strip polls `GET /api/analytics/realtime`, and the view's server shell resolves that request's sources and goal names before rendering.

It requires a signed-in user and `access.read`. Every answer, success or failure, carries `Cache-Control: private, no-store`: the engine already caches, and the scope of an answer depends on the caller's cookies, so no shared cache may ever hold one. Every refusal is the plugin-wide [error envelope](#errors), whose table lists each code this endpoint answers and when.

### Parameters

| Parameter | Shape | Default | Validation |
|---|---|---|---|
| `metrics` | comma list of metric keys | required | 1 to 10 after dedupe; every entry a known metric, and one the source serves |
| `dimensions` | comma list of dimension keys | none (totals only) | at most 2 after dedupe; every entry in `capabilities.dimensions` |
| `from` | `YYYY-MM-DD`, or an ISO datetime carrying `Z` or an offset | required | a real calendar day |
| `to` | same as `from` | required | not before `from`; the window must not exceed 366 days |
| `granularity` | `minute`, `hour`, `day`, `week`, `month` | none (no time series) | not finer than `capabilities.minGranularity` |
| `filters` | JSON array of `{ dimension, operator, value }` | none | at most 10; each dimension in `capabilities.filters`, each operator in `capabilities.filterOperators`, each value 1 to 256 characters |
| `limit` | integer | `50` | 1 to 500 |
| `order` | `<metric>:asc` or `<metric>:desc` | the adapter's own order | the metric must be one of `metrics` |
| `compare` | `previous` | none | only when `capabilities.comparison`, and only for a range with a comparable previous window. A previous window beyond the source's lookback is dropped rather than rejected |
| `source` | a source id from the sources endpoint | the request's default source | must be a source this request resolves |
| `path` | string | none | at most 512 characters |
| `hostname` | string | none | at most 253 characters |
| `timezone` | IANA zone | the request's resolved [reporting timezone](/analytics/timezone) | must be a zone the runtime knows |
| `scope` | string, or `*` for every scope | the request's own scope | honored only for platform readers |

Unknown parameters are ignored, and a parameter that is present but blank is treated as absent. Rules are evaluated in a fixed order and the first failure wins, so a request with two problems is told about the first one: timezone, metrics, dimensions, `from`/`to`, granularity, filters, limit, order, compare, path, hostname.

A value outside the contract's own union is `invalid_param`; a contract-valid value the selected source does not serve gets its own `unsupported_*` code. Asking for a `limit` above 500 is a rejection, not a clamp.

### Dates and the reporting timezone

A date-only bound (`2026-09-01`) means the **whole calendar day in the effective timezone**: `from` is that day's first instant, `to` is its last, so the `to` day is included in full. The effective timezone is the `timezone` parameter when given, otherwise whatever `reportingTimezone` resolves for this request.

A datetime bound must carry `Z` or a `±HH:MM` offset (`2026-09-01T06:00:00+02:00`) and is taken as the instant it names. An offset-less datetime is rejected rather than read in the server process's own zone, and so are the loose forms `Date` would otherwise accept (`2026`, `Sep 1 2026`).

Windows longer than 366 days answer `range_too_long`. Shorter ones can still be narrowed: the engine clamps the range's start to the source's `maxLookbackDays` and sets `result.meta.clamped: true`. The echoed `query` is what you **asked** for, before that clamp, so `meta.clamped` is how a client learns the read covered less than the request named.

### Response

```jsonc
{
  "result": {
    "rows": [{ "dimensions": { "page": "/pricing" }, "metrics": { "pageviews": 812 } }],
    "totals": { "pageviews": 4120 },
    "meta": {
      "provider": "native",
      "fetchedAt": "2026-09-07T23:59:59.999Z"
      // "clamped": true  the range was narrowed to the source's maxLookbackDays
      // "sampled": true  the adapter hit its own row cap
      // "stale": true    an expired cache entry was served because the refresh failed
      // "unappliedFilters": [...]  filters the source could not carry, so the rows are wider
      // "goalsUnresolved": true    the goal numbers are absent from this read
    }
  },
  "comparison": { "...": "..." },  // an AnalyticsResult over the previous window, asked for with compare=previous
  "source": { "id": "native", "label": "Native", "kind": "config" },
  "capabilities": { "metrics": ["pageviews"], "...": "..." },
  "query": {
    "metrics": ["pageviews"],
    "dateRange": { "start": "2026-09-01T00:00:00.000Z", "end": "2026-09-07T23:59:59.999Z" },
    "limit": 50,
    "goalSlugs": ["signup"],  // the scope's slugs, [] when it configures none, or the string "unresolved" when resolving them failed; absent when the read asks about no goals
    "timezone": "UTC"
  }
}
```

`query` is the request after validation and defaulting, with the date range as ISO instants, so a client renders the window it actually got rather than the one it typed. `meta` is passed through from the engine untouched: `meta.stale` is `true` when a cache entry expired, the refresh failed, and the expired value was served instead (see [stale-while-error](/analytics/cache)), which is worth surfacing as a badge rather than an error.

`comparison` is the equal-length window immediately preceding the range, aligned to whole days in the effective timezone (the `timezone` parameter when given, otherwise the one the plugin's resolver returned). It is asked for with `compare=previous` and omitted when that window starts before the source's `maxLookbackDays`, measured from today: the read is served without it rather than failed, so a client renders the numbers and drops the delta.

`meta.unappliedFilters` lists the narrowing a source could not carry, which means the rows answer a wider question than the request asked: `filters` entries it had to drop (an `eq` value with a comma on Umami among them), and on Umami a goal slug whose comma its value list cannot escape. `meta.goalsUnresolved` says the read's goal numbers could not be resolved: the goal resolver failed, the caller sent no goal slugs, or the provider rejected the goal request and the rest of the read was served without it. A scope that simply has no goals configured answers an empty goal table instead, with no flag. Neither is an error, and both are worth captioning rather than hiding. The echoed `query.goalSlugs` is how a client tells the two apart: the scope's slugs, an empty list for a scope that configured none, or the string `"unresolved"` when the resolver failed. The view and the widgets do exactly that: an unapplied filter raises a notice beside the range caption, and a goal read with no rows renders its own empty state (the goals could not be read, or none are configured for this scope) rather than the plain no-data one, so it never reads as nobody having converted.

<Callout type="warn">
**A far-past absolute range is served unclamped, but loses its comparison.** The engine's clamp floors a read at that read's **own end** minus the source's lookback, so a window that is itself shorter than the lookback is never narrowed however far back it sits. The comparison guard measures from **today** instead, because that is where a provider measures its own lookback from, so such a range answers in full and its previous window is dropped.
</Callout>

<Callout type="info">
**An unconfigured source answers `200`, not an error.** A source whose credentials are unset returns an empty `rows` array, no `totals`, and `meta.provider` set to its adapter id. The read is short-circuited before any network call, so nothing distinguishes it from a real window with no traffic. If that matters to your surface, check the source's configuration rather than inferring it from an empty result.
</Callout>

### Examples

Top pages over a week, busiest first:

```http
GET /api/analytics/query?metrics=pageviews,visitors&dimensions=page&from=2026-09-01&to=2026-09-07&order=pageviews:desc&limit=10
```

```jsonc
{
  "result": {
    "rows": [
      { "dimensions": { "page": "/pricing" }, "metrics": { "pageviews": 812, "visitors": 604 } },
      { "dimensions": { "page": "/blog/launch" }, "metrics": { "pageviews": 455, "visitors": 402 } }
    ],
    "totals": { "pageviews": 4120, "visitors": 2980 },
    "meta": { "provider": "native", "fetchedAt": "2026-09-07T23:59:59.999Z" }
  },
  "source": { "id": "native", "label": "Native", "kind": "config" },
  "capabilities": { "...": "..." },
  "query": { "...": "..." }
}
```

Conversions and revenue per [goal](/analytics/goals) for August, against July:

```http
GET /api/analytics/query?metrics=conversions,revenue&dimensions=goal&from=2026-08-01&to=2026-08-31&compare=previous
```

`comparison` then carries the same shape over `2026-07-01` to `2026-07-31`, ready to diff row by row.

Daily pageviews from Germany only. `filters` is a JSON array, so URL-encode it:

```http
GET /api/analytics/query?metrics=pageviews&granularity=day&from=2026-09-01&to=2026-09-07&filters=%5B%7B%22dimension%22%3A%22country%22%2C%22operator%22%3A%22eq%22%2C%22value%22%3A%22DE%22%7D%5D
```

```ts
// the same filter, built rather than typed
const filters = JSON.stringify([{ dimension: 'country', operator: 'eq', value: 'DE' }])
const url = `/api/analytics/query?metrics=pageviews&granularity=day&from=2026-09-01&to=2026-09-07&filters=${encodeURIComponent(filters)}`
```

A source whose `capabilities.filters` does not list `country` answers `unsupported_filter` instead, which is the signal to drop the filter chip rather than to retry.

### From admin code

`fetchQuery` wraps the endpoint for client components, with the credentials, the JSON handling and an in-flight dedupe already done:

```tsx title="TopPages.tsx"
'use client'

import { fetchQuery, QueryFetchError } from '@10x-media/analytics/client'
import type { AnalyticsRow } from '@10x-media/analytics/types'
import { useConfig } from '@payloadcms/ui'
import { useEffect, useState } from 'react'

export const TopPages = () => {
  const {
    config: {
      routes: { api },
    },
  } = useConfig()
  const [rows, setRows] = useState<AnalyticsRow[]>([])

  useEffect(() => {
    const controller = new AbortController()
    fetchQuery(
      api,
      {
        metrics: ['pageviews', 'visitors'],
        dimensions: ['page'],
        from: '2026-09-01',
        to: '2026-09-07',
        order: { metric: 'pageviews', direction: 'desc' },
        limit: 10,
      },
      { signal: controller.signal },
    )
      .then(({ result }) => setRows(result.rows))
      .catch((err: unknown) => {
        if (err instanceof QueryFetchError) {
          // err.status, err.error?.code, err.error?.param, err.retryAfter
        }
      })
    return () => controller.abort()
  }, [api])

  return <ul>{rows.map((row) => <li key={row.dimensions?.page}>{row.dimensions?.page}</li>)}</ul>
}
```

- `buildQueryUrl(apiRoute, request)` returns the same URL without fetching it, written in a fixed field order so two requests with identical values always produce the same string. A trailing slash on `apiRoute` is normalized, so `routes.api` in either form produces one URL and one dedupe key.
- Concurrent calls for one URL share a single fetch; the entry clears on settle, so a later call refetches and a failed one retries. A caller's `AbortSignal` (`fetchQuery(api, request, { signal })`) rejects that caller alone and deliberately leaves the shared fetch running for everyone else waiting on it.
- Any non-2xx throws `QueryFetchError` with `status` always set. `error` carries the [envelope](#errors)'s `code` and `message` (plus `param` when one applies), so branch on `error.code` and fall back to `status`. It is left undefined for a body this release cannot read: one that is not the envelope, and one carrying a code a newer server added, which is reported as a generic failure rather than typed into a lie. `retryAfter` is a whole number of seconds: a fractional header floors, and the HTTP-date form of `Retry-After` yields no value at all. A network-level failure propagates as itself.

`QueryRequest` takes an optional `scope`. Omit it and the helper reads the caller's own scope, which is what an admin surface wants. Set it and the endpoint honors it only for platform readers; everyone else gets `400 untrusted_scope`.

`QueryRequest` and the response types are exported from `@10x-media/analytics/types`, along with `DIMENSION_KEYS` and `FILTER_OPERATORS` for building pickers of your own.

## Refresh endpoint

```http
POST /api/analytics/refresh
Content-Type: application/json

{ "scope": "acme" }
```

It bumps one scope's [cache epoch](/analytics/cache#invalidation), which retires every cached read keyed on the old one across every instance, and answers the new token:

```json
{ "epoch": "mu70fj8y-bbbad86a" }
```

The token is opaque. It is a value to compare for change, never one to parse, order or count with. The answer carries `Cache-Control: private, no-store`.

The body is optional and carries one optional `scope`. An empty body, a body that is not a JSON object, a body with no `scope`, and a `scope` that is blank once trimmed all mean the caller's own resolved scope, so a bare `POST` with nothing at all is the ordinary call. A body larger than 4 KiB answers `413 payload_too_large`; one that could not be read answers `400 invalid_param` with `param: 'scope'`.

Authentication and `access.read` gate it exactly as they gate the read endpoints. Scope is then decided by the same code the query endpoint reads with, so this endpoint refuses every request that endpoint refuses. Naming any scope is a cross-scope decision and requires `access.platformRead`, so a tenant naming another tenant's scope gets `400 untrusted_scope` rather than a silent no-op. A request that resolves no scope at all on a scoped install is `untrusted_scope` too, unless the caller has `access.platformRead`: null usually means no tenant is selected rather than "everything", and the install-wide token it would otherwise bump is the one every cross-scope read keys on.

Its refusals are the same [error envelope](#errors) every other endpoint answers, listed there with the rest.

`scope: "*"` bumps the install-wide token rather than every scope's, because a cross-scope read stamps no scope on its query and its entries key on exactly that token. See [Cross-scope entries](/analytics/cache#cross-scope-entries-key-on-the-install-wide-token).

An instance bumps a given scope at most once every five seconds for this endpoint. Inside that window the call answers `200` with the token already in force, without retiring anything again, so a looped `POST` cannot turn one scope's cached reads into provider calls over and over. The collection hooks are not debounced: a saved provider or goal document is always visible on the next read. This is a debounce of invalidation, not request rate limiting, which belongs in front of Payload.

`refreshCache` wraps it for client components, beside `fetchQuery`:

```ts
import { refreshCache } from '@10x-media/analytics/client'

const { epoch } = await refreshCache(api)                       // the caller's own scope
await refreshCache(api, { scope: 'acme', signal })              // platform readers only
```

Unlike `fetchQuery` it is not deduped: a reader pressing Refresh twice means it twice, and the `AbortSignal` goes straight to the fetch because no other caller shares it. Any non-2xx throws `QueryFetchError`, with the same `status`, `error` and `retryAfter` a failed read carries. An answer whose `epoch` this client cannot read is reported as `'0'` rather than typed into a lie, since callers act on the refresh having happened rather than on the token.

A refresh invalidates; it does not re-read. Nothing is fetched from the source until a surface asks, so the next read of that scope pays the cold round trip.

## Errors

Every endpoint the plugin registers answers a refusal in one shape, with one vocabulary of codes, whatever it refused. This section is the reference for all of them: the endpoints described here, and the [document](/analytics/display-fields), [realtime](/analytics/widgets), [goals](/analytics/goals) and [native ingest](/analytics/native#the-ingest-endpoint) endpoints described elsewhere.

```jsonc
{
  "error": {
    "code": "unsupported_metric",                 // one of the codes below
    "message": "source does not serve revenue",   // safe to render
    "param": "metrics"                            // absent when nothing single is at fault
  }
}
```

`code` is what to branch on, `message` is what to show, and `param` names the query parameter, body field or event field at fault when one is. Messages are safe to display: adapter configuration and upstream error text never reach the response.

Every error answer built from the envelope carries `Cache-Control: private, no-store`, the public ingest endpoint's included (the capture proxy below is the exception on both counts), and so does every successful answer whose content depends on the caller's scope: query, refresh, sources, goals, document and realtime. The [tracker config](/analytics/capture) endpoint is the one scope-dependent answer that is cached at all, and privately: `private, max-age=60` with `Vary: Host, Cookie`. It has no refusal of its own, which is why it has no row below. Every `503 unavailable` carries `Retry-After: 30`, so a client backs off identically whether the plugin is still booting or a source is down.

### The codes

| `error.code` | Status | What it means |
|---|---|---|
| `invalid_param` | `400` | a parameter, body field or event field is missing or malformed |
| `unsupported_metric` | `400` | a known metric the selected source does not serve |
| `unsupported_dimension` | `400` | a known dimension the source cannot break down by |
| `unsupported_filter` | `400` | a dimension outside `capabilities.filters` |
| `unsupported_operator` | `400` | an operator outside `capabilities.filterOperators` |
| `unsupported_granularity` | `400` | finer than `capabilities.minGranularity` |
| `range_too_long` | `400` | the window exceeds 366 days |
| `untrusted_scope` | `400` | a scope this caller may not read or refresh |
| `unauthorized` | `401` | no signed-in user |
| `forbidden` | `403` | `access.read` denied the request, or the source is not readable under this scope |
| `not_found` | `404` | the document asked about is unbound, missing, or not this caller's to read |
| `unknown_source` | `404` | no source resolves for the request, or the named one is outside its registry |
| `payload_too_large` | `413` | the request body is over that endpoint's cap |
| `internal` | `500` | an unexpected failure; the detail is logged, never returned |
| `unavailable` | `503` | the plugin runtime is not ready, or a source failed with no cached entry to serve |

The union is exported as `AnalyticsErrorCode`, with the values as `ANALYTICS_ERROR_CODES`. It is open to additions, so treat a code you do not recognize as a generic failure of its status rather than exhausting over it.

| `/analytics/realtime` | `403` | `forbidden` | | `access.read` denied the request |
| `/analytics/realtime` | `500` | `internal` | | the request failed before the read, which is a configuration bug rather than an outage: an `access.read` resolver that throws is the case to look for |
| `/analytics/realtime` | `503` | `unavailable` | | the source threw; the widget polls every few seconds, so an outage is retryable rather than a stack trace per poll |
| `/analytics/document` | `400` | `invalid_param` | `from` or `to` | `timeframe=custom` with a bound that will not parse. An inverted window blames `to`, since `from` is the one the reader picked first |
| `/analytics/document` | `401` | `unauthorized` | | no signed-in user |
| `/analytics/document` | `403` | `forbidden` | | `access.read` denied the request |
| `/analytics/document` | `404` | `not_found` | | the collection is not bound, the `id` is missing, the document does not exist, or this caller may not read it. The four are deliberately one answer |
| `/analytics/document` | `500` | `internal` | | the document read failed for any other reason; logged with the collection slug |
| `/analytics/document` | `503` | `unavailable` | | the plugin runtime is not ready on this Payload instance |
| `/analytics/ingest` | `400` | `invalid_param` | the first field at fault | `type`, `path`, `hostname` or `name` is missing or invalid, checked in that order. Unparseable JSON names `type`. A body that died in transit sends no `param` |
| `/analytics/ingest` | `413` | `payload_too_large` | | the body is over 64 KiB |

<Callout type="warn">
`403` with `param: 'source'` is not an error state to shout about. The sources endpoint lists a shared config adapter for every scope (it always has), but **reading** it under a tenant scope would be a cross-scope read, so it fails closed behind `access.platformRead`. The picker and the endpoint agree on which sources exist, not on which are readable; treat it as "this source is not readable for your scope" and let the user pick another.
</Callout>

### Reading a code from admin code

`readErrorCode` answers the code of a parsed body, and `undefined` for anything it cannot read: a body that is not the envelope, and a code this release does not know. A client therefore never branches on a word it cannot act on.

```ts
import { readErrorCode } from '@10x-media/analytics/client'

const res = await fetch(`${api}/analytics/sources`, { credentials: 'include' })
if (!res.ok) {
  const code = readErrorCode(await res.json().catch(() => null))
  // 'unauthorized' and 'forbidden' will not fix themselves on a retry; anything else may
  const permanent = code === 'unauthorized' || code === 'forbidden'
}
```

`readResponseError` is the same read over a `Response` nothing has parsed yet, so the `catch` above is not yours to write: it answers the whole error (`code`, `message` and `param`), and `undefined` for a body that is not JSON, an empty one and an already-consumed one included, rather than throwing.

```ts
import { readResponseError } from '@10x-media/analytics/client'

const res = await fetch(`${api}/analytics/sources`, { credentials: 'include' })
const error = res.ok ? undefined : await readResponseError(res)
```

`fetchQuery` and `refreshCache` already do this: `QueryFetchError.error` is the same parsed envelope. The plugin's own pickers and the realtime counter read the code the same way, which is why the counter stops polling on a `401` or a `403` and keeps polling through a `503`.

`readErrorCode` is exported from `@10x-media/analytics/client` and `@10x-media/analytics/types`, both of which also export the `AnalyticsError` and `AnalyticsErrorCode` types; `readResponseError` from `@10x-media/analytics/client`; `ANALYTICS_ERROR_CODES` comes from `@10x-media/analytics/types` and the package root, and the builder `analyticsError` from the root. `QueryError` and `QueryErrorCode` are aliases of `AnalyticsError` and `AnalyticsErrorCode`, kept so existing imports keep compiling.

### The one endpoint with no envelope

The [capture proxy](/analytics/proxy) (`/analytics/p/:slot/*`) answers its `400`, `404`, `405`, `413` and `502` with no body at all, and no code. It relays a vendor SDK's own traffic, and that SDK, not admin code, reads the answer; a JSON envelope in the middle of a PostHog batch response would be noise to the only consumer there is. Read those statuses as [the proxy documents them](/analytics/proxy#runtime-endpoint), and expect nothing to parse: the `405` carries `Allow: GET, POST, OPTIONS` and that is the whole answer.

## Multi-tenancy

Scope comes from the request, exactly as it does everywhere else: the plugin's `scopeResolver` decides it, and the endpoint reads the sources that scope resolves. There is no way for a tenant to read another tenant's numbers by asking.

- An explicit `scope` parameter is honored **only** for platform readers. Anyone else gets `400 untrusted_scope`, whatever the value.
- `scope=*` reads every scope at once, behind the same `access.platformRead` gate.
- On a scoped install, a request resolving no scope at all is ambiguous rather than install-wide (it usually means no tenant is selected), so it fails closed: `404 unknown_source`.
- A `scopeResolver` that answers the platform wildcard (`*`) for a given request is itself a cross-scope resolution, so it too requires `access.platformRead`. Without it, that request resolves no sources at all, on this endpoint and on the sources endpoint.
- A shared config adapter that cannot filter by scope is listed for a tenant but not readable by one: see the `403` note above.

A platform reader meets the other half of that last rule. Passing `scope=<tenant>` for a config adapter without `scopedQueries` is **allowed**, because `access.platformRead` grants it, but the adapter still cannot narrow the query, so the answer is install-wide totals rather than that tenant's. The echoed `query` is how a client tells: it carries no `scope` key, because none was stamped on the read. Treat a missing `query.scope` on a scoped request as "these numbers are not scoped", and label the surface accordingly instead of captioning install-wide totals with a tenant's name.

Granting `access.read` never widens which scope a user reads. The two gates are independent, and scope gating always applies.

See [Multi-tenancy](/analytics/multi-tenancy) for the full recipe.
