---
title: Scope
description: Freeze everything, a group, or individual collections and globals.
---

A window freezes **everything** unless you turn off **Lock everything** and pick what it covers.

## Groups

Groups are named sets of collections and globals, defined once in the config and picked per window:

```ts
contentLock({
  groups: [
    { key: 'catalog', label: 'Catalog', collections: ['products', 'categories'] },
    { key: 'site', label: { en: 'Website', de: 'Webseite' }, collections: ['pages', 'posts'], globals: ['header', 'footer'] },
  ],
})
```

- A window stores the group's `key`, so a collection added to a group is covered by every window on it. Renaming a key detaches existing windows from the group.
- `label` is a string or a map per admin language. It shows in the window form and the banner.
- The build fails when a group names a collection or global the config does not have, or when two groups share a key.

## Individual collections and globals

```ts
contentLock({ individualSelection: true })
```

adds an **Advanced** section to the window with raw collection and global pickers, for the one-off that no group fits. Pass `{ access: ({ req }) => boolean }` instead of `true` to show those pickers only to some users. Entities already covered by a picked group are not repeated in the banner.

## Always writable

Some collections stay writable during every lock:

- the lock collection itself;
- Payload's system collections: `payload-preferences`, `payload-locked-documents`, `payload-jobs`, `payload-kv`, `payload-migrations`;
- everything in `exempt`.

```ts
contentLock({ exempt: ['form-submissions', 'newsletter-signups'] })
```

Use `exempt` for collections the public site writes to, which should keep accepting submissions while editors are frozen out. Payload's folders collection is covered like any other.
