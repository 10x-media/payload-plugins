---
title: Content Lock
description: Planned and unplanned maintenance windows that freeze content on every channel.
---

`@10x-media/content-lock` freezes content while you do something to it that editors must not race: a database migration, a bulk import, a content audit, a relaunch. While a lock is active, every write to the frozen collections and globals is rejected, the admin turns read-only, and a banner tells everyone why and until when.

```ts title="payload.config.ts"
import { buildConfig } from 'payload'
import { contentLock } from '@10x-media/content-lock'

export default buildConfig({
  plugins: [contentLock({})],
})
```

That adds a **Content locks** collection. Create a window in it (or press **Lock now** in its list) and the lock is on.

## How it works

A lock is a document in the `content-locks` collection: a **window** with a start, an optional end, an optional announcement, and a scope. Many windows can exist at once, scheduled weeks ahead or started on the spot. Each moves through stages derived from the clock (pending, announced, active, ended), so nothing has to run on a timer for a lock to start or end.

When a window is active, the plugin blocks writes in two layers:

- **A guard** (`beforeOperation`) on every covered collection and global rejects `create`, `update`, `delete`, autosave and version restores with a `503` and a `Retry-After` header. It runs on REST, GraphQL, the admin, and the Local API, **including `overrideAccess: true`**. This is the layer that guarantees nothing gets written.
- **Access wrapping** makes `create`, `update` and `delete` access return `false` in scope, so the admin renders documents read-only and hides Save, Create and Delete instead of letting editors run into an error.

Reads are never affected. The plugin's own collection and Payload's system collections (preferences, locked documents, jobs, kv, migrations) are always writable, so logins, preferences and the lock itself keep working.

## What editors see

- A **banner** above the admin, one window at a time with a pager: what is frozen, from when, until when, or a message you write per window and per locale.
- Announcements before the lock, dismissible per user. An active lock cannot be dismissed.
- Read-only documents in scope, with collections out of scope untouched.

## When to use it

Whenever a change to stored content needs the content to hold still: migrations and reindexes, imports that overwrite editorial data, restoring a backup, a freeze before a launch. Scope a window to a group (the catalog, the website) so the rest of the admin keeps working, or lock everything.
