---
title: Webhooks
description: Outbound webhook subscriptions for Payload v3, with signing, retries, and a delivery log.
---

`@10x-media/webhooks` delivers signed HTTP POSTs whenever documents in opted-in collections are created, updated, or deleted. Subscribers are managed in the admin panel or registered in code; deliveries run inline or through Payload's jobs queue and land in an append-only log with a redeliver button.

```ts title="payload.config.ts"
import { buildConfig } from 'payload'
import { webhooks } from '@10x-media/webhooks'

export default buildConfig({
  plugins: [
    webhooks({
      collections: {
        posts: true,
        orders: { operations: ['create', 'delete'] },
      },
    }),
  ],
})
```

## Features

- **Opt-in collections**: `true` for all three operations, or pick operations and add a `transform` to reshape or redact the payload.
- **Two subscription sources**: admin-managed records and hard-coded [code subscriptions](/webhooks/subscriptions#code-subscriptions), merged at delivery time.
- **[Delivery modes](/webhooks/deliveries)**: queued through Payload jobs (with retries and timeouts) or inline in the hook; `auto` picks based on whether a job runner exists.
- **[HMAC signing](/webhooks/signing)** with reveal-once secrets, plus id, event, and timestamp headers on every request.
- **A delivery log** collection: status, response code, duration, the exact body sent, and one-click redelivery.
- **Composes with the [jobs family](/concepts/jobs-family)**: installing [Jobs](/jobs) switches delivery to the queue automatically; installing [Automations](/automations) registers a `webhook` trigger slug for the future inbound phase.

## When to use it

Use it to push Payload changes into external systems (CRMs, search indexes, Slack, custom services) without polling. It is outbound-only today; inbound webhooks are a planned phase.
