---
title: Audit fields
description: Payload's own createdBy and updatedBy, shown on the document through the plugin's read-only field.
---

Audit fields answer "who owns this document right now" from the document, with no join into the log. On Payload 4 they are Payload's: its `authorship` adds `createdBy` and `updatedBy` to every collection and global when the config has an auth collection, and stamps them on every write. They are hidden in the admin by default, and the plugin writes nothing to them.

`authorshipFields` makes them visible, drawn by the plugin's read-only component. It works with the log switched off entirely:

```ts title="payload.config.ts"
auditLogs({
  authorshipFields: true,
})
```

`true` covers every collection and global the config has when the plugin runs. Name them to cover only some:

```ts
auditLogs({
  authorshipFields: { collections: ['posts', 'pages'], globals: ['site-settings'] },
})
```

Off by default: without it, the fields are stored and queryable as usual and stay out of the edit view.

## What Payload does with them

Payload owns the stamping, the storage and the access:

- `createdBy` is set on create, `updatedBy` on every create and update, from `req.user`.
- Both are relationships to every auth collection, stored as `{ relationTo, value }`.
- Nobody can write them through the API; an update that sends them is ignored.
- `authorship: false` on a collection or global turns both off, `authorship: { updatedBy: false }` one of them. Payload's [authorship docs](https://payloadcms.com/docs/configuration/collections) have the details.

The plugin respects all of it. A field that `authorship` switches off gets nothing, and a collection that declares its own `createdBy` or `updatedBy` keeps its field as declared, which Payload then leaves alone too.

## The field component

The plugin replaces the relationship select with a read-only component showing the user as plain text. If the current user can read the related collection, it becomes a link that opens the document in a drawer; if not, it stays text. Nobody gets a select they cannot use.

To label, place or draw them differently, declare the fields yourself with Payload's factories and leave `authorshipFields` off for that collection:

```ts title="collections/Posts.ts"
import { createCreatedByField, createUpdatedByField } from 'payload'

export const Posts: CollectionConfig = {
  slug: 'posts',
  fields: [
    // ...
    createCreatedByField({
      overrides: {
        admin: {
          components: { Field: '@10x-media/audit-logs/client#AuditRelationshipField' },
          hidden: false,
          position: 'sidebar',
        },
        label: 'Author',
      },
    }),
    createUpdatedByField({ overrides: { admin: { hidden: false } } }),
  ],
}
```

The factories bring Payload's hooks and access along, so the fields are still stamped; Payload sees the names taken and adds nothing. They belong at the top level of the fields, where Payload looks for them.

## Fields of your own

`auditRelationshipField` builds a read-only relationship drawn by the same component, for a field the plugin and Payload do not manage. Filling it is your job; it exists so a `reviewedBy` looks and behaves like the two Payload owns:

```ts title="collections/Posts.ts"
import { auditRelationshipField } from '@10x-media/audit-logs'

export const Posts: CollectionConfig = {
  slug: 'posts',
  fields: [
    auditRelationshipField({ name: 'reviewedBy', label: 'Reviewed By', relationTo: 'users' }),
  ],
}
```

| Option | Default | Description |
|---|---|---|
| `name` | required | Field name in the database and in form state. |
| `relationTo` | required | The collection or collections it relates to. |
| `label` | none | Admin label. |
| `admin` | `{}` | Merged over the plugin's (`readOnly: true` and its component). `admin.components.Field` wins. |

## Coming from the Payload 3 line

The plugin used to add and stamp its own `createdBy` and `lastModifiedBy`. They are gone, with `auditFields`, `defaults`, `createdByField` and `lastModifiedByField`; [Upgrading](/audit-logs/upgrading#payload-4) has the data to move across.
