---
title: Calculations and scoring
description: Derived numeric fields from a safe expression engine for totals, quotes, and quiz scores.
---

A `calculation` field derives its value from a serializable expression over other answers. The client computes it live for display; the server recomputes it from scratch at submit and stores only its own result. The client's number is discarded.

Set `calcDisplay: false` on the field to compute without rendering (a hidden total or quiz score that [conditions](/form-builder/conditions) and validation can still reference).

## The expression AST

Expressions are plain JSON with a `type` discriminant. No `eval`, no `Function`, no untrusted code:

| Node | Shape | Notes |
|---|---|---|
| `lit` | `{ type: 'lit', value: number }` | Literal |
| `ref` | `{ type: 'ref', field: string }` | Another field's answer |
| `op` | `{ type: 'op', op: '+' \| '-' \| '*' \| '/' \| '%', left, right }` | Arithmetic |
| `neg` | `{ type: 'neg', operand }` | Negation |
| `fn` | `{ type: 'fn', fn: 'min' \| 'max' \| 'round' \| 'abs' \| 'ceil' \| 'floor', args }` | Math functions |
| `weight` | `{ type: 'weight', field: string, weights: Record<string, number> }` | Maps an option answer to a score |

A price total:

```ts
import type { CalcExpression } from '@10x-media/form-builder'

const total: CalcExpression = {
  type: 'op',
  op: '*',
  left: { type: 'ref', field: 'qty' },
  right: { type: 'ref', field: 'unitPrice' },
}
```

A quiz score:

```ts
const scoreQ1: CalcExpression = {
  type: 'weight',
  field: 'q1',
  weights: { a: 10, b: 0, c: 5 },
}
```

## Authoring in the admin

The `expression` config field renders a visual builder that reads left to right, the way the calculation is spoken: a first value, then one step per operation, then an optional finishing function. An empty expression starts with a **Start with** picker naming what each value kind is for:

| Builder label | Node | What it offers |
|---|---|---|
| Field | `ref` | A select of the fields this calculation may reference: `number` fields, plus earlier `calculation` fields (see [forward references](#forward-references) below). |
| Number | `lit` | A plain numeric input. |
| Weighted field | `weight` | A `select` field to score, then a number input per one of its options, turning the chosen option into a number you define. |
| Function | `fn` | A function select (`min`, `max`, `round`, `abs`, `ceil`, `floor`) over one or more arguments, each its own chain, with add/remove buttons for `min`/`max`'s variadic args. |

**Add step** appends an operation row (`+ - * / %` plus a value); steps apply in order to the running result, and the live preview renders the parenthesized reading on every edit, marking an unfilled slot with `?`. **Then apply** wraps the finished chain in a single-argument function (`round`, `abs`, `ceil`, `floor`). Each row removes with its trailing button; removing the first row promotes the next, and a remove control is only rendered where removal is genuinely possible.

An order total with tax, built as Field `price`, then `× ` Field `quantity`, then `× ` Number `1.19`, reads back as `price × quantity × 1.19` in the preview and stores:

```ts
import type { CalcExpression } from '@10x-media/form-builder'

const total: CalcExpression = {
  type: 'op',
  op: '*',
  left: {
    type: 'op',
    op: '*',
    left: { type: 'ref', field: 'price' },
    right: { type: 'ref', field: 'quantity' },
  },
  right: { type: 'lit', value: 1.19 },
}
```

A quiz score, built as Weighted field over a `q1` select, with a weight typed in next to each of its options (`a` → 10, `b` → 0, `c` → 5):

```ts
const scoreQ1: CalcExpression = {
  type: 'weight',
  field: 'q1',
  weights: { a: 10, b: 0, c: 5 },
}
```

The builder is a view onto the stored `CalcExpression` JSON, not a separate format: an expression written through the API (or seeded programmatically) opens in the builder as the equivalent chain, with right-nested math rendered as a group.

Validity is still enforced on save server-side: an expression that does not normalize into a well-formed tree is rejected with a field error, so a broken calculation cannot reach the public form, regardless of which editor produced it.

### Forward references

A calculation can reference a `number` field declared anywhere on the form, but another `calculation` field only if it is declared *earlier* in the fields list. The engine folds calculations in declaration order, so a forward or self reference would always evaluate to `0`; the builder's Answer picker enforces this by only offering earlier calculations, not later ones, keeping the authoring UI honest about what will actually compute.

## Totality and safety

The evaluator always produces a finite number: division or modulo by zero yields `0`, a missing `ref` yields `0`, an unknown `weight` key yields `0`, and recursion is depth-guarded (max 64). It runs on the public submit path for every submission, so these properties are load-bearing, not niceties.

## Using the engine directly

`evaluateCalc`, `computeCalcFields`, `calcExpressionOf`, and `normalizeCalc` are exported from the root and from `./react`, so custom layouts compute with the identical engine:

```ts
import { evaluateCalc, computeCalcFields } from '@10x-media/form-builder/react'

evaluateCalc({ type: 'ref', field: 'qty' }, { qty: 3 }) // 3
const updatedValues = computeCalcFields(fields, currentValues)
```

## Downstream

Because the stored value is server-authoritative, calculation fields participate everywhere ordinary fields do: `visibleWhen`/`validateWhen` conditions, validation rules, and [recall](/form-builder/recall-prefill) (`You scored {{score}} points!`).
