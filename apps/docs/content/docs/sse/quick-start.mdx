## Install

```bash
pnpm add @10x-media/sse
```

## Configure

```ts title="payload.config.ts"
import { buildConfig } from 'payload'
import { sse } from '@10x-media/sse'

export default buildConfig({
  // ...
  plugins: [
    sse({
      collections: {
        posts: true,
        // or: posts: { thinEvents: false, events: ['create', 'update', 'delete'] },
      },
      presence: true,
      admin: true,
    }),
  ],
})
```

| Option | Meaning |
|---|---|
| `collections` | Opt-in map. `true` enables create/update/delete with thin events. |
| `presence` | `true` / object enables viewer presence; omit or `false` disables. |
| `presence.profile` | Admin chip click: `none` (default), `drawer`, or `newTab`. Hover always shows the identify label. |
| `admin` | Omit/`false` off. `true` enables live list, presence chips (if presence is on), and the dirty-document conflict banner; or `{ liveList?, presence?, conflict? }`. `liveList` may be `{ field: 'title' }` to pick the Cell target. `conflict: false` disables the banner. |
| `scope` | Omit/`false` off. `true` uses `multiTenantScope()`; or `{ resolveRequest, resolveDoc }`. |
| `broker` | Custom `EventBroker` for multi-instance. Default is in-process. |
| `heartbeatMs` | Stream comment heartbeat interval (default 15s, floor 1s). |
| `maxConnectionsPerUser` | Concurrent streams per user **per process** (default 8). Over the cap returns 429. |

Autosave writes (`req.query.autosave`) do not publish. Draft editors that need live fan-out should save without the autosave query.

Regenerate the import map after installing so admin components resolve:

```bash
pnpm generate:importmap
```

(or your project's usual `payload generate:importmap`).

## Stream URL

Authenticated GET:

```
/api/realtime/stream?topics=posts
/api/realtime/stream?topics=posts:abc123
/api/realtime/stream?topics=posts,posts:abc123
```

Topics are comma-separated. Empty topics return 400; at most 32 topics. Anonymous requests return 401. See [Security](/sse/security).

## Client hooks

```ts
import {
  usePayloadDocument,
  usePayloadList,
  useDocumentPresence,
  usePayloadSubscription,
} from '@10x-media/sse/client'
```

- **`usePayloadDocument({ collection, id })`**: document topic; bumps `revision` on thin events, sets `doc` when enriched.
- **`usePayloadList({ collection })`**: collection topic; bumps `generation` on create/update/delete so you refetch the list.
- **`useDocumentPresence(collection, id, { mode })`**: join/leave and peer list. `mode` is `viewing` or `editing` (advisory).
- **`usePayloadSubscription({ topics, onEvent })`**: low-level fetch SSE wrapper.

Pass `token` when the browser cannot rely on cookies alone.

## Presence

```ts
sse({
  collections: { posts: true },
  presence: {
    heartbeatMs: 10_000,
    leaseMs: 30_000,
    profile: 'drawer',
    identify: (user) => ({ id: String(user.id), label: String(user.name ?? user.id) }),
  },
})
```

Default `identify` label is `name`, then `email`, then `id`. A custom `identify` still wins. Endpoints: `POST` / `DELETE` `/api/realtime/presence` with `{ collection, id, mode? }`. `mode` is `viewing` (default) or `editing`. Omit `mode` on heartbeat to keep the current value.

Admin chips bind `mode` to form dirty: first keystroke publishes `editing` over SSE so other open tabs update immediately. The chip ring and row copy (`also viewing`, `{name} is editing`, `{name} and {other} are editing`) are awareness only. They do not lock the form or reject save. Two saves can still overwrite. Payload `lockDocuments` is unchanged; turn it off on the collection if you do not want its modal on top of the chips.

`presence.profile` is admin-only. Omit or `none` keeps chips as hover-only. `drawer` opens the viewer's user document in Payload's document drawer. `newTab` opens `{adminRoute}/collections/{usersSlug}/{peer.id}`. If `users.read` is self-only, drawer and new-tab return 403. That is host ACL.

## Admin live list

With `admin: true` (or `admin: { liveList: true }`), opted-in collection list views sync over SSE and flash changed rows. Presence chips appear on the edit view when admin presence is on. Chips show viewing vs editing. They are not a lock.

When `admin.conflict` is on (the default whenever admin is on), a dirty edit form shows a banner if someone else updates or deletes that document. Reload dumps local form state. Keep editing dismisses the banner; save still last-write-wins. A clean form does not auto-refetch. Autosave writes do not publish, so they do not trip the banner. The component registers on `edit.beforeDocumentControls` so it can run on the edit view, then portals the banner below Payload's save toolbar (that slot is a fixed-height nowrap bar). Another tab of the **same user** is treated as your own write and does not banner. Reconnect does not replay, so a write while the stream is down can be missed. Presence plus conflict uses two SSE connections per edit view; raise `maxConnectionsPerUser` if you open many tabs.

## Emit from the server

```ts
import { getSSE } from '@10x-media/sse'

const { emit } = getSSE(payload)
emit({
  id: crypto.randomUUID(),
  topic: 'posts',
  event: 'update',
  collection: 'posts',
  docId: 'abc',
  timestamp: Date.now(),
})
```

## Multi-instance

The default broker is in-process. Supply your own `broker` implementing `EventBroker` (`publish`, `subscribe`, `destroy`) so events cross nodes. Without that, other nodes' clients are only as fresh as their refetch interval.
