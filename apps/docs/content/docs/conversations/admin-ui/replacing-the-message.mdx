---
title: Replacing the message
description: Draw every message in the admin with your own component, from the config or per view.
---

[Slots](/conversations/admin-ui/slots) add to a message. To change the message itself (another layout, a different header, a compact log style) replace it. There are two ways, and both reach every place a message is drawn: feeds, thread roots and thread replies.

| | Where | Reaches |
|---|---|---|
| `components.Message` | Instance option, a Payload component path | Everywhere the instance is drawn in the admin, the `comments()` drawer included |
| `renderMessage` | React prop on `ChatDrawer`, `ChatPanel`, `ChatThread`, `ChatFeed` | That component and what it renders |

When both are set, `renderMessage` wins. Without either, `ChatMessage` draws the message.

## From the config

```ts title="payload.config.ts"
conversations({
  slug: 'comments',
  // ...
  components: {
    Message: '/components/CommentMessage#CommentMessage',
  },
})
```

The path is registered in `admin.dependencies`, so run `payload generate:importmap` after setting it. The component must be a client component (`'use client'`). A server component is skipped with a warning in the log, and the default is used: a message renders too often, and changes too often, to go through a server round trip each time.

It receives `ChatMessageProps`, the same props `ChatMessage` gets:

| Prop | |
|---|---|
| `message` | The message, as the window holds it (`WindowMessage`: a `ConversationMessage` plus `sendStatus` while sending or failed) |
| `authors` | The `authors` map: `{ [userKey]: { name, avatar?, deleted? } }` |
| `instance` | The instance slug |
| `viewer` | The viewer's user key, or `null` |
| `compact` | A follow-up from the same author, drawn without avatar and name |
| `readOnly` | The channel takes no writes from the viewer |
| `onOpenThread` | Present in a feed, absent inside a thread and on a thread's root |
| `threadReadAt` | When the viewer last read this message's thread |
| `renderType` | The view's renderer for non-`text` types, if any |
| `header`, `footer`, `actions` | Prop slots, usually unset here |

## Wrapping the default

The easiest replacement renders `ChatMessage` itself and fills its prop slots. Everything else (editing, deleting, the menu, thread summaries, placeholders) keeps working.

```tsx title="components/CommentMessage.tsx"
'use client'
import { ChatMessage, type ChatMessageProps } from '@10x-media/conversations/client'

export const CommentMessage = (props: ChatMessageProps) => {
  const { message } = props
  return (
    <ChatMessage
      {...props}
      footer={message.mentions?.length ? <small>{message.mentions.length} mentioned</small> : null}
      header={props.compact ? undefined : <MessageHeader {...props} />}
    />
  )
}
```

`header` replaces the name and time line. `footer` goes under the body, before the `messageFooter` slot. `actions` adds menu items before the `messageActions` slot. Rendering `ChatMessage` inside the replacement does not loop: `ChatMessage` never consults `components.Message`.

## Drawing your own

For a message that looks nothing like the default, build it from the headless pieces:

- `useMessage({ message, readOnly, threadReadAt, viewer })` from `@10x-media/conversations/react`: `own`, `deleted`, `canEdit`, `canDelete` (already read-only aware), `editing` and `setEditing`, `save`, `remove`, `replies` and `hasNewReplies`.
- `MessageBody` from `/react`: the body through Lexical's JSX converters, with mentions named from `authors`. Pass `useChatRichText().converters` so a project's own rich text renders.
- `MessageMenu` and `Avatar` from `/client`, if you want the admin's menu and avatars.
- `ChatComposer` with `initialBody`, `onSave` and `onCancel` for inline editing.
- `useTypeRenderer(instance)` from `/client` for non-`text` messages.

```tsx title="components/LogMessage.tsx"
'use client'
import {
  ChatComposer,
  type ChatMessageProps,
  MessageMenu,
  useChatRichText,
  useTypeRenderer,
} from '@10x-media/conversations/client'
import { absoluteTime, MessageBody, useMessage } from '@10x-media/conversations/react'
import { ConfirmationModal, useModal, useTranslation } from '@payloadcms/ui'

export const LogMessage = ({
  authors,
  instance,
  message,
  onOpenThread,
  readOnly,
  renderType,
  threadReadAt,
  viewer,
}: ChatMessageProps) => {
  const state = useMessage({ message, readOnly, threadReadAt, viewer })
  const { converters } = useChatRichText()
  const renderConfiguredType = useTypeRenderer(instance)
  const { openModal } = useModal()
  const { i18n } = useTranslation()
  const confirmSlug = `log-delete-${String(message.id)}`

  return (
    <div className="log-message" data-message-id={String(message.id)}>
      <time dateTime={message.createdAt}>{absoluteTime(message.createdAt, i18n.language)}</time>
      <strong>{authors[message.authorKey]?.name}</strong>
      {state.deleted ? (
        <em>deleted</em>
      ) : state.editing ? (
        <ChatComposer
          channel={message.channel}
          conversationKey={message.key}
          initialBody={message.body}
          instance={instance}
          onCancel={() => state.setEditing(false)}
          onSave={state.save}
          parent={message.parent ?? null}
        />
      ) : message.type === 'text' ? (
        <MessageBody authors={authors} converters={converters} message={message} />
      ) : (
        (renderType?.(message) ?? renderConfiguredType(message))
      )}
      {state.replies > 0 && onOpenThread ? (
        <button onClick={() => onOpenThread(message)} type="button">
          {state.replies} replies{state.hasNewReplies ? ', new' : ''}
        </button>
      ) : null}
      {state.deleted || state.editing || message.sendStatus ? null : (
        <MessageMenu
          instance={instance}
          message={message}
          onDelete={() => openModal(confirmSlug)}
          onEdit={() => state.setEditing(true)}
          onOpenThread={onOpenThread}
          own={state.canDelete}
        />
      )}
      {state.canDelete ? (
        <ConfirmationModal
          body="The message is removed for everyone."
          heading="Delete message"
          modalSlug={confirmSlug}
          onConfirm={state.remove}
        />
      ) : null}
    </div>
  )
}
```

`MessageMenu` also renders the `messageQuickActions` and `messageActions` slots, so extension items such as reactions stay available. Render the `messageFooter` slot yourself with `<ChatSlot name="messageFooter" ... />` from `/client` if extensions put things there.

### What a replacement has to handle

- **Compact rows.** Consecutive messages by one author within five minutes arrive with `compact: true`. Drop the avatar and name there, or the grouping looks broken.
- **Deleted messages.** A deleted message has `deletedAt` set and its content wiped on the server. It still arrives while it anchors a thread (or always, with `deleted: 'placeholder'`), and it may still carry extension data such as reactions.
- **Sending state.** An optimistic message has `sendStatus: 'sending'` and a temporary `local:<clientId>` id until the server confirms it, and `sendStatus: 'failed'` if the send failed (the composer offers Retry). Offer no menu while `sendStatus` is set.
- **Read-only channels.** Pass `readOnly` to `useMessage`; `canEdit` and `canDelete` then stay false.
- **Threads.** `onOpenThread` is absent inside a thread and on its root. Show the thread summary only when it is set. `threadReadAt` decides whether replies are new.
- **Custom types.** A message whose `type` is not `text` has no body to render. Use `renderType`, then `useTypeRenderer`.
- **Anchors.** Keep `data-message-id` on the outer element if anything in your project scrolls to messages.

## Per view: renderMessage

In code, pass `renderMessage` to `ChatDrawer`, `ChatPanel`, `ChatThread` or `ChatFeed`. It is a function of the same props:

```tsx
import { ChatMessage, ChatPanel } from '@10x-media/conversations/client'

<ChatPanel
  conversationKey={key}
  instance="tickets"
  threadSlug={`ticket-${id}-thread`}
  renderMessage={(props) =>
    props.message.authorKey.startsWith('customers:') ? (
      <ChatMessage {...props} header={<CustomerHeader {...props} />} />
    ) : (
      <ChatMessage {...props} />
    )
  }
/>
```

`ChatPanel` hands it to the feed and to the thread drawer, `ChatThread` to its root and replies. `MessageView` (from `/client`) is the component behind both routes: it takes `ChatMessageProps` plus `render` and picks `render`, then `components.Message`, then `ChatMessage`. Use it when you draw rows yourself and still want the instance's replacement.

## On a website

The website components come from the [shadcn registry](/conversations/website/shadcn-registry) and are copied into your project, so there is nothing to configure: edit `conversation-message.tsx` directly, or build the message from the hooks in [Headless](/conversations/website/headless).
